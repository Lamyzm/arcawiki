# ADR-0006. 파이프라인은 코드가 돌리고, AI 가 필요한 지점만 위임한다

- 상태: 채택
- 날짜: 2026-08-11

## 맥락

ADR-0002 에서 "생성 주체는 Claude Code" 라고 정했더니, 실제 진행은 내가 터미널에서
`python crawler.py` 를 손으로 치는 형태가 됐다. 그것은 위임이 아니라 수작업이다.

수집·파싱·적재·중복제거·변경감지는 판단이 필요 없는 결정적 작업이다. LLM 이
개입할 이유가 없고, 사람이 명령을 칠 이유도 없다.

## 결정

작업을 두 종류로 나누고 경계를 명확히 한다.

**코드가 자동으로 (Docker 안에서, 사람 손 안 탐)**

- 크롤링 (스케줄)
- 파싱 → `posts/*.json`
- DB 적재 (멱등)
- 변경 감지 (`content_hash` 비교)
- **작업 큐 적재** — "이 글은 아직 지식 추출이 안 됐다", "이 문서의 원문이 바뀌었다"

**Claude Code 에 위임 (내가 스킬을 호출할 때)**

- 큐에서 할 일을 꺼낸다
- 판단이 필요한 것만 처리: 지식 추출, 주장 통합, 문서 작성·갱신
- 결과를 DB 에 쓴다

**웹**은 읽기 전용으로 DB 를 조회한다 (ADR-0002 유지).

## 이유

- 결정적 작업을 LLM 이나 사람이 돌리면 느리고 비싸고 빠뜨린다.
- 큐가 있으면 "무엇이 처리되지 않았는가" 가 DB 상태로 드러난다. 내가 기억할
  필요가 없고, 세션이 끊겨도 남는다.
- LLM 호출 지점이 한 곳으로 모여서, 비용과 품질을 그 지점에서만 통제하면 된다.
- 자동화된 부분과 위임된 부분의 경계가 곧 "판단이 필요한가" 의 경계라서,
  나중에 어느 쪽을 손볼지 판단하기 쉽다.

## 필요한 것

스키마에 작업 큐가 없다. 추가한다.

- 어떤 대상(글 / 섹션 / 문서)에 대해
- 어떤 작업(추출 / 문서생성 / 갱신)이
- 왜 필요한지(신규 / 원문변경 / 요청)
- 처리됐는지

큐는 코드가 채우고 Claude 가 비운다. 양쪽이 같은 테이블을 본다.

## 결과

- `crawler.py` 는 사람이 치는 명령이 아니라 컨테이너의 정기 작업이 된다.
- `ingest.py` 도 마찬가지로 자동 실행된다.
- 내가 하는 일은 "스킬 호출" 하나로 줄어든다. 무엇을 처리할지는 큐가 정한다.
- 큐가 비어 있으면 할 일이 없는 것이고, 쌓여 있으면 얼마나 밀렸는지 눈에 보인다.
