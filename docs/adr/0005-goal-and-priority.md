# ADR-0005. 목표는 제작 능력이고, 위키는 그 압축 수단이다

- 상태: 채택
- 날짜: 2026-08-11

## 맥락

여기까지 위키를 만드는 방법만 정하고, **왜 만드는지**를 명시하지 않은 채로 진행했다.
그 결과 허브 큐레이션을 그대로 따르는 설계(ADR-0004)가 나왔는데, 목표를 알고 보니
그 설계가 우선순위를 거꾸로 잡고 있었다.

실제 목표 사슬:

```
AI로 짤·비디오를 잘 만들기          ← 진짜 목적
   ↑ 자료 1,138건을 다 읽을 수는 없다
정제된 데이터로 압축
   ↑
친구와 공유하는 위키
   ↑ 만드는 과정 자체가
Claude 와 대화하며 구축
```

## 결정

**성공 지표는 "원문을 읽지 않고도 잘 만들게 되는가" 다.** 문서의 완성도나 분량이 아니다.

우선순위를 **제작에 필요한 순서**로 다시 잡는다. 허브 큐레이션 유무가 아니라.

| 순위 | 주제 | 근거 |
|---|---|---|
| 1 | 비디오 생성 (MiniMax H3, Wan) | 목표에 직결. 정리된 자료가 사실상 없음 |
| 2 | ANIMA / 최신 이미지 모델 | 현재 주력. 2026년 자료가 300건인데 정리 없음 |
| 3 | ComfyUI 워크플로우·설치 | 위 둘의 실행 환경 |
| 4 | VRAM·최적화 | 8GB 환경 제약이 실제 병목 |
| 5 | 프롬프트 | 자료 많고 허브 정리도 있음 |
| 6 | LoRA 학습 | 2023년 자료 위주. 급하지 않음 |
| 7 | 2023년 고전 (WebUI, SD1.5) | 배경 지식 |

## 실측 근거

수집 1,138건 시점, 주제별 자료량과 허브 큐레이션 유무:

| 주제 | 전체 | 2026년 | 허브가 가리킨 것 |
|---|---|---|---|
| 비디오/영상 | 175 | 150 | **25** |
| ANIMA | 311 | 300 | **11** |
| ComfyUI | 373 | 350 | 23 |
| NAI | 131 | 90 | 42 |
| 프롬프트 | 424 | 295 | 129 |
| 업스케일/화질 | 150 | 108 | 42 |
| LoRA 학습 | 27 | 17 | 10 |

**갈리는 지점이 뚜렷하다.** 허브가 잘 정리해 둔 것은 옛 주제(NAI, 프롬프트)이고,
목표에 직결되는 최신 주제(비디오, ANIMA)는 자료가 많은데도 아무도 정리하지 않았다.

즉 **이 프로젝트의 값어치는 허브를 옮겨 적는 데 있지 않고, 허브가 비워 둔 2026년
구간을 정리하는 데 있다.**

## ADR-0004 에 대한 수정

문서 단위를 "허브 섹션 그대로"로 정했으나, 비디오·ANIMA 에는 대응하는 허브 섹션이
없다. 따라서 두 갈래로 둔다.

- **허브 섹션이 있는 주제** — 섹션을 그대로 문서 단위로 쓴다 (기존 결정 유지)
- **허브 섹션이 없는 주제** — 주제 묶음을 내가 만들고, 그 근거(어떤 글들을 왜 묶었는지)를
  문서에 남긴다. 사람 분류가 없으므로 판단이 들어간다는 사실을 드러낸다.

시점 표시(`as_of`) 결정은 그대로 유지한다. 2026년 구간은 오히려 변화가 빨라서 더 중요하다.

## 결과

- 다음 작업은 2026년 미정리 구간의 추가 수집이다. 허브 추적은 끝났다(318건 확보).
- 첫 실전 문서는 비디오 또는 ANIMA 가 된다. LoRA 학습 문서는 형식 검증용 목업으로 남긴다.
- 압축률을 눈으로 볼 수 있어야 한다. 문서마다 "원문 N건 → 이 문서 하나"를 표시한다.
