# ADR-0001. PostgreSQL 을 두 소비자의 공유 기반으로 삼는다

- 상태: 채택
- 날짜: 2026-08-11

## 맥락

이 위키에는 소비자가 둘이다.

1. **웹** — 친구들과 내가 브라우저에서 검색하고 읽는다. CF 터널로 공개한다.
2. **Claude Code** — 내가 터미널에서 직접 물어보고, 문서를 만들고, 고친다.

처음에는 산출물을 마크다운 파일로 잡았다. 생성 비용이 싸고 335건 규모에는
ripgrep 으로 충분하다는 이유였다. 그러나 그것은 *생성* 을 기준으로 한 판단이고,
이 프로젝트의 목적은 *공유와 정제* 다.

마크다운의 한계:

- 친구가 열 URL 이 없다.
- 재생성하면 사람이 고친 내용이 덮어써진다.
- 산문으로 쓰는 순간 구조가 사라져서 "LoRA 학습률 관련 주장만 모아봐" 같은
  질의가 불가능하다. 마크다운은 종착 포맷이다.

## 결정

PostgreSQL 을 단일 기반으로 두고, 웹과 Claude Code 가 **같은 DB** 를 본다.
마크다운은 DB 에서 뽑아내는 출력물 중 하나일 뿐 원본이 아니다.

Claude Code 는 `posts/*.json` 을 읽지 않고 DB 에 질의한다. 파일은 크롤러의
중간 산출물이며, 적재가 끝나면 DB 가 사실상의 원본이다.

## 이유

- 두 소비자가 같은 사실을 본다. 웹에서 보이는 것과 Claude 가 답하는 것이
  어긋나지 않는다.
- 항목 단위로 쪼개 두면 사람이 고친 것을 표시하고 보존할 수 있다.
- 구조가 남아 있으면 같은 데이터로 여러 형태(가이드/검색결과/목록)를 만들 수 있다.

## 결과

- 스키마 설계가 선행 작업이 된다. 대충 넣고 나중에 고치기 어렵다.
- 로컬 Postgres 를 항상 띄워둬야 한다 (Docker).
- 크롤러 → 파일 → DB 의 적재 단계가 하나 늘어난다. 대신 파서를 고쳤을 때
  재크롤 없이 재적재할 수 있도록 원본 JSON 을 `posts.raw` 에 함께 보관한다.

## 대안

- **마크다운 + git**: 친구 공유와 편집 보존이 안 된다. 기각.
- **클라우드 DB(Neon 등)**: 로컬 CF 터널 호스팅으로 정해져서 불필요. 기각.
- **파일 + 벡터 인덱스만**: 편집·이력·권한을 담을 곳이 없다. 기각.
