# 용어집

> **원문 120건 → 이 문서 하나** · 주장 337개 · 정리 2026-08-14

채널 글을 읽다 막히는 낱말을 한자리에 모았다. **한 줄 정의 + 실제로 쓰는 값**이 짝이다.
값이 적힌 것은 채널 원문에서 실제로 확인된 수치이고, 시점이 다르면 시점을 밝혀 두었다.
전체 그림은 [처음이라면](overview.md)에 있다.

## 1. 기본 — 이것부터 알면 화면이 읽힌다
<small>2026-07 기준 · 근거 12건</small>

| 낱말 | 한 줄 정의 | 실제로 쓰는 값 |
|---|---|---|
| **체크포인트 / 모델** | 이미지를 학습한 결과 파일. 그림을 뽑는 본체. SD 를 붕어빵 기계라 하면 형틀에 해당 | `.ckpt` / `.safetensors`, 2~7.2GB. 2026-08 권장은 Illustrious 계열(WAI-illustrious-SDXL) 또는 ANIMA |
| **VAE** | 이미지를 잠재 공간으로 인코딩·디코딩하는 부분. 색감과 선명도를 정한다. 모델에 내장돼 있어 필수는 아니다 | 300~400MB, `.vae.pt`. **결과가 물 빠진 듯 흐리면 VAE 를 안 넣은 것** |
| **프롬프트** | 원하는 그림을 영어 단어를 콤마로 구분해 적는 주문 | `girl, blonde hair, standing` |
| **네거티브 프롬프트** | 원치 않는 요소를 적는 칸 (orange hair 를 원하는데 오렌지 과일이 나오면 여기에 orange) | 2026년 관례: `worst quality, low quality, score_1, score_2, score_3, blurry, jpeg artifacts` |
| **시드(seed)** | 생성의 기반이 되는 노이즈를 가리키는 숫자열. 같으면 비슷한 그림이 나온다 | `-1` 은 랜덤 |

| **디노이즈 강도** | i2i 에서 원본을 얼마나 자유롭게 바꿀지 | `0` 이면 원본 그대로. 빈 Latent 에서 시작하는 t2i 는 반드시 `1` |
| **배치 크기 / 배치 수** | 한 번에 동시 생성하는 장수 / 그 작업을 몇 번 반복할지 | 배치 크기가 크면 VRAM 부족 위험 |
| **클립스킵(Clip Skip)** | 텍스트 인코더의 마지막 몇 층을 건너뛸지 | WebUI 설정 키는 `CLIP_stop_at_last_layers`. ComfyUI 에서는 `CLIP Set Last Layer` 노드에 **음수**를 넣는다 |

**CFG 와 디노이즈는 짝으로 이해한다** — CFG 가 **프롬프트**를 얼마나 참고할지라면 디노이즈 강도는 **참고 이미지**를 얼마나 참고할지다. 원리상 참고 이미지에 노이즈를 얼마나 강하게 주고 시작할지를 정하는 값이다.

**배치를 쓸 때 함정** — 각 이미지의 시드는 최초 시드에서 `+1, +2, +3 …` 으로 늘어난다. 그래서 배치 수와 배치 크기를 **둘 다** 1보다 크게 잡으면 시드가 겹쳐 같은 그림이 나온다(최초 703905855 로 2×4 를 뽑으면 세 장이 중복). 여러 장을 뽑을 때는 **한쪽만** 늘린다.

**Illustrious/NoobAI 계열의 기본값 감각** — 병합 모델 배포글들이 제시하는 값은 대체로 `Euler` 계열 / CFG **4.5~5** / **28스텝** / **1024x1024** 로 모인다.

## 1-b. 샘플러 이름 읽는 법
<small>2026-08 기준 · 근거 5건</small>

**샘플러가 하는 일** — 디퓨전 모델은 원래 노이즈를 1000번 걷어내야 이미지가 된다. 그걸 몇 스텝만에 **근사**하는 방법이 샘플러이고, **근사 방식의 차이가 곧 샘플러의 차이**다.
그래서 샘플러 이야기에서 말하는 '성능'은 그림이 예쁘냐가 아니라 **적은 스텝으로 1000회 결과에 얼마나 가까워지느냐**(연산 속도)를 뜻한다.

**이름에 붙는 글자**

| 글자 | 뜻 |
|---|---|
| `2` | 2차 샘플러 |
| `S` | Singlestep — 스텝마다 모델을 2번 추론해 스텝당 2배 느리다 |
| `M` | Multistep — Singlestep 고차 샘플러의 불안정성을 푼 것. 안정적이고 빠르다 |
| `a` | Ancestral — 스텝마다 노이즈를 더 넣어 **변화가 큰** 결과가 나온다. 성능 차이는 없고 성격만 다르다 |
| `SDE` | 스텝 수는 적지만 스텝당 2배 느리다. 같은 시간이면 Multistep 이 낫다 |
| `Karras` | Karras noise schedule. 같은 스텝에서 품질이 오른다 (~50스텝 구간) |

이대로 읽으면 `dpmpp_2m_sde_gpu` 는 **2차 Multistep + SDE + GPU 노이즈**다.

> **시점 주의** — 2023년 SD1.5 시절의 결론은 `DPM++ 2M Karras` 였고 "Euler 는 DPM 과 비교조차 안 될 만큼 안 좋다"였다. **이 판단은 SDXL 시대에 뒤집혔다.** 지금은 Illustrious/NoobAI 가 `Euler` · `Euler A`, ANIMA 가 `ER SDE` / `er_sde` + `simple` 을 쓴다.

## 1-c. 파일 형식 — `.ckpt` / `.safetensors` / fp16 / EMA
<small>⚠️ 2023-02 기준 · 근거 6건 · 자료 엇갈림</small>

이름 뒤에 붙는 표기가 무엇을 뜻하는지 몰라 같은 모델을 여러 번 받는 일이 흔하다.

| 표기 | 뜻 |
|---|---|
| `.ckpt` | 파이썬 pickle 기반 저장 형식. 담긴 내용은 safetensors 와 같다 |
| `.safetensors` | **악성코드가 실행될 수 없는 안전한 컨테이너 형식.** 담긴 내용도 성능도 `.ckpt` 와 같다 |
| `fp32` / `fp16`(=`half`) | 가중치를 32비트로 저장하느냐 16비트로 저장하느냐. fp16 이 용량 절반이고 **기능은 같다** |
| `EMA` | 학습에만 쓰이는 별도 가중치 묶음. **그림 생성·병합·LoRA 사용에는 전혀 필요 없다** |
| `pruned` | EMA 를 떼어 낸 것 |

**용량은 이렇게 결정된다** — 확장자가 아니라 fp16 여부와 EMA 포함 여부다.

```
7GB    = EMA 약 3GB + fp32 가중치 약 4GB
  ↓  fp32 → fp16
4~5GB
  ↓  EMA 제거 (no-ema / pruned)
2GB
```

> ⚠️ **자주 보이는 틀린 설명 — "safetensors 는 학습 데이터를 포함한 대용량, half 는 저용량".**
> **이 설명은 틀렸다.** safetensors 는 **파일 컨테이너 형식일 뿐이라 용량과 무관하다.**
> 2023년 병합 안내글 본문에 이렇게 적혀 있었고, 같은 시기의 다른 글 셋이 반대로 확인한다 —
> `.ckpt` 와 `.safetensors` 는 담긴 내용이 같고 safetensors 가 더 안전한 컨테이너일 뿐이며,
> fp16 과 fp32 는 기능이 같으니 용량 작은 fp16 을 고르면 된다는 것이다.

받은 모델이 너무 크면 직접 줄일 수도 있다 — A1111 의 **Model Converter** 확장에서
Precision `fp16` / Pruning Methods `no-ema` / Checkpoint Format `safetensors` 로 두면 7GB 가 2GB 가 된다.
시드를 고정해 검증했을 때 차이는 머리 장식 유무 정도로 미미했고(그마저 xformers 탓일 수 있다는 지적이 있다),
다만 **AnythingV3 계열은 예외**라는 단서가 붙어 있다 (2023-02, SD1.5 기준).

> ⚠️ **WebUI 의 '체크포인트 병합' 탭으로 줄이는 방법은 반쪽짜리다.** 주 모델만 지정하고
> Multiplier `0` · 보간 `None` · **`Save as float16` 체크**로 Merge 하면 7GB 가 4GB 가 되지만,
> 이것은 **fp32 → fp16 변환일 뿐이고 EMA 가중치는 그대로 남는다**(댓글 정정).
> 제대로 줄이려면 `https://github.com/Akegarasu/sd-webui-model-converter` 로
> **fp16 + no-ema 를 걸어 2GB** 까지, fp32 를 유지하더라도 **no-ema 만으로 3GB** 까지 줄인다.
> 체크할 항목이 fp16 · no-ema · ckpt/safetensors 셋뿐이라 오히려 더 직관적이다.

요즘 모델의 `Q8_0` · `fp8` · `int8convrot` 같은 표기는 성격이 다른 **양자화** 방식이다 → [모델 고르기](models.md)

## 2. 보조 모델 — 체크포인트 위에 얹는 것들
<small>2026-06 기준 · 근거 13건</small>

LoRA·임베딩·하이퍼네트워크는 전부 **단독으로는 그림을 못 만들고 체크포인트에 얹어 쓰는 보조 모델**이다.
확장자(`.pt` / `.safetensors` / `.bin`)만으로는 종류를 구분할 수 없고 **용량으로 판별**해야 한다.

### 넷의 차이를 한 번에 외우는 비유 — 모델(체크포인트)을 '뇌' 라고 하면

2023년 1월 글이 붙인 비유인데, 지금도 입문자에게 가장 잘 통한다.

| 방식 | 비유 | 하는 일 | 용량 | 넣는 곳 · 부르는 법 |
|---|---|---|---|---|
| **임베딩** (Textual Inversion) | **전자책** | AI 가 모르는 낱말을 넣어도 반영이 안 되는데, '그 낱말을 네가 이미 아는 지식으로 이렇게 만들면 된다' 고 알려 주는 설명서 | **1KB~300KB** | `embeddings` / 프롬프트에 파일명 (`embedding:이름`) |
| **하이퍼네트워크** | **최면** | 모델이 이미 아는 것을 잘 안 꺼낼 때(타율이 낮을 때) 사고방식을 비틀어 자주 꺼내게 만든다 | **20MB~수백MB** | `models/hypernetworks` / `<hypernet:파일명:1>` |
| **드림부스** | **세뇌** | 뇌 자체를 개조한다. 모르던 것도 알게 만들 수 있어 성능이 가장 좋다 | 결과물이 **모델 한 개**(GB 단위) | `models/Stable-diffusion` |
| **LoRA** | **세뇌 임플란트**(기억이 담긴 USB) | 드림부스 기반이되 **삽입할 일부 기억만** 담는다 | 하이퍼네트워크와 비슷하거나 더 작음 | `models/lora` / `<lora:파일명:1>` |

**넷을 가르는 선 하나** — 임베딩과 하이퍼네트워크는 **모델이 이미 아는 것을 꺼내는** 방식이라
모델이 아예 모르는 개념은 만들어 낼 수 없다. **모르던 것을 새로 알게 만드는 것은 드림부스(와 그 파생인 LoRA)뿐**이다.
드림부스에서 과학습으로 모델이 망가지는 것을 막는 가이드라인이 **정규화 이미지**이고, 학습 때 정해지는 호출용 단어가 **트리거 워드**다.

### 왜 하이퍼네트워크로는 애니풍을 실사로 못 바꾸나 — QKV 를 찰흙으로 보면 된다

| 기호 | 정체 | 찰흙 비유 |
|---|---|---|
| **Q** (Query) | 이미지의 기저 정보 | 찰흙이라는 **소재** |
| **K** (Key) | 텍스트·조건의 기저 정보 | 그 찰흙으로 뭘 만들지 내리는 **명령** |
| **V** (Value) | 텍스트에서 이미지로 연결되는 정보 | 실제로 찰흙을 **주무르는 것** |

Key 와 Query 의 상관 정도로 attention 밀도를 얻고 그것으로 Value 를 수정해 결과를 낸다.
**하이퍼네트워크는 Q 를 건드리지 않고 KV 만 학습한다** — 소재는 그대로 두고 무엇을 어떻게 만들지만 바꾸는 셈이라,
애니풍을 실사로 바꾸는 것 같은 전환은 원리상 불가능하다(원문의 표현으로는 "찰흙에 물감 대신 붓질로 그림을 그리겠다는 소리").
드림부스가 **모든 가중치를 재조정**하는 것과 갈리는 지점이 여기다.

> **시점 주의** — 임베딩·하이퍼네트워크·드림부스는 2022~2023년 자료의 주인공이다.
> 지금 실제로 쓰는 것은 사실상 **LoRA 뿐**이고, 하이퍼네트워크는 거의 안 쓰이며
> 임베딩은 `lazypos`·`lazyneg`·`lazyhand` 같은 품질 보정용으로만 남았다.

### 지금 쓰는 것들 — 한 줄 정의

| 낱말 | 한 줄 정의 | 용량·값 |
|---|---|---|
| **LoRA(로라)** | 특정 그림체·캐릭터를 뽑기 위해 따로 학습시킨 보조 모델 | 모델 버전이 맞아야 목록에 보인다. ANIMA 에는 ILXL 로라를 못 쓴다 |
| **임베딩 (Textual Inversion)** | 프롬프트 안에서 `embedding:이름` 으로 부르는 보조 모델 | **1MB 이하**, `.pt`. `lazypos` · `lazyneg` · `lazyhand` 가 널리 쓰인다 |
| **하이퍼네트워크** | 임베딩과 같은 `.pt` 라 용량으로 구분한다. 지금은 거의 안 쓴다 | 21MB~1GB |
| **드림부스** | 보조 모델이 아니라 기존 모델 자체를 세부조정해 **새 모델**을 만드는 방식 | 학습 VRAM 최소 12GB · 실질 16GB · 권장 24GB |
| **컨트롤넷(ControlNet)** | 포즈·선화·깊이 같은 조건 이미지로 구도를 강제하는 보조 모델 | 오픈포즈 / depth / inpainting / union 등. `models\controlnet` 에 넣는다 |
| **LLLite** | **LoRA Like Lite**. 조건 이미지를 한 장짜리 로라처럼 쓰는 경량 컨트롤넷 | ANIMA 용으로 lineart · inpainting · Tile & Repair 가 있다 |

**로라를 여러 개 겹칠 수 있는 이유** — LoRA 는 원본 모델 `W0` 는 그대로 두고 파인튜닝 차이 `ΔW` 를 `B(d×r) × A(r×k)` 로 쪼개 학습한다. 파라미터가 `d×k` 에서 `(d+k)×r` 로 줄어들고, 합칠 때도 원본에 `BA` 만 더하면 되므로 **모듈처럼 붙였다 뗐다** 할 수 있다. `<lora:이름:가중치>` 를 여러 개 쓸 수 있는 것이 이 때문이다.

**rank(r)와 alpha(α)** — 학습 설정에서 자주 보이는 값이다. 논문은 `ΔW` 에 `α/r` 을 곱하고 α 를 1 로 고정했는데, SD 로라가 `r=128` 을 유행시키면서 α=1 이면 실제 학습률이 1/128 로 토막나 **로라가 아예 작동하지 않는** 사고가 있었다. 그래서 high rank 면 **α = r** 로 두어 스케일링을 없애고 learning rate 만 조절한다.

## 5. 프롬프트 문법 용어
<small>2026-08 기준 · 근거 26건</small>

| 낱말 | 한 줄 정의 | 실제 표기 |
|---|---|---|
| **태그** | 단부루(Danbooru)에 실제로 존재하는 낱말. 지어내면 안 된다 | 게시물 수 **500 미만**인 태그는 재현율이 낮아 대체 태그를 찾는 편이 낫다 |
| **가중치 (A1111 계열)** | 태그의 세기를 조절 | `(태그:1.2)`. 괄호 한 겹당 1.1배 — `(((검은머리)))` 는 1.1³ = 1.331배 |
| **가중치 (NovelAI 계열)** | NAI 의 세기 표기. 숫자가 **앞**에 온다 | `weight::tag ::` — **닫는 `::` 앞 공백이 정본**이다(`1.2::blue eyes ::`). 음수도 되어 `-1::tears, bags under eyes ::`. 다만 `2::태그::` 처럼 공백을 뺀 표기도 널리 유통돼 갈린다 → [프롬프트 쓰는 법](prompting.md) · [NovelAI](nai.md) |
| **음수 가중치** | 요소를 빼는 데 쓴다 | `(choker:-1)` 처럼 **일반 프롬프트 칸**에 적는다. ComfyUI 는 negpip 계열 노드가 있어야 동작 |
| **이스케이프** | 태그 안의 괄호를 문자로 처리 | `nagisa \(blue archive\)`, `graphite \(medium\)` |
| **퀄리티 태그** | 화질을 끌어올리려고 앞머리에 두는 관용 태그 | 2026년: `masterpiece, best quality, highres, absurdres` / 2022년: `masterpiece, best quality` 두 개뿐이었다 |
| **스코어 태그** | 포니 계열에서 유래한 9단계 평점 태그 | 긍정에 `score_9`/`score_8`/`score_7` 중 1~3개, 네거티브에 `score_1`~`score_3` |
| **와일드카드** | 목록 파일에서 하나를 무작위로 뽑아 넣는 문법 | `__파일명__` (하위 폴더는 `__폴더/파일명__`). `##name##` 순차, `##name*N##` N번 반복, `__=name__` 한 사이클 유지 |
| **다이나믹 프롬프트** | 중괄호로 그 자리에서 하나를 고르는 문법 | `{A\|B\|C}`. `//` 한 줄 주석, `/* */` 블록 주석 |
| **인원수 태그** | 사람 수를 앞머리에 못박는 태그 | `1girl` / `2girls`. 2명 이상이면 선두에 두고 `solo` 와 병용하지 않는다 |
| **작가 태그** | 화풍을 부르는 태그 | ANIMA 는 반드시 `@` 로 시작 — 단부루 등록명이 `aaaaa_bbb` 면 `@aaaaa bbb` |
| **NAI 내장 랜덤** | 확장 없이 NAI 가 자체 지원하는 랜덤 문법 | `\|\|A\|B\|C\|\|`. 앞뒤에 파이프를 하나 더 둔 `\|\|A\|B\|C\| \|\|` 는 **'아무것도 안 나옴' 도 후보**가 되고, `5::\|\|A\|B\|C\|\|::` 로 그룹 전체에 가중치를 건다 |
| **스텝 스케줄링** | 스텝 도중에 프롬프트를 넣고 빼는 문법 | `[tag::n]` = **n스텝까지 넣었다 뺀다** / `[tag:n]` = **n스텝부터 넣는다** / `[A\|B]` = 스텝마다 교대 |
| **`BREAK`** | 75토큰 청크 경계를 원하는 위치에서 강제로 일으키는 키워드 | **대문자 단독 토큰이어야 한다.** `BREAK:` 처럼 콜론을 붙이면 다른 토큰이 되어 작동하지 않는다 |
| **`ADDCOMM` / `ADDROW` / `ADDCOL` / `ADDBASE`** | A1111 Regional Prompter 의 영역 구분자 | `ADDCOMM` 앞부분이 **모든 영역 공통**, `ADDROW` 로 나눈 덩어리가 **위에서 아래로 한 행씩** 배정된다 |
| **`target#` / `source#`** | NAI 캐릭터 프롬프트에서 상호작용의 방향을 지정하는 접두 | `target#grabbing another's breasts` — **태그 앞**에 붙인다(`#Target` 이 아니다). 상호작용 태그는 하나만 남긴다 |
| **미드저니 가중치** | SD·NAI 어느 쪽과도 다른 제3의 문법 | `abstract::1.04` — 태그 뒤에 콜론 두 개. **음수도 된다**(`noise::-0.05`). 괄호 가중치는 지원하지 않는다 |
| **네거티브 임베딩** | 장문 네거티브를 한 토큰으로 압축한 임베딩 파일 | `EasyNegative` · `badhandv4` · `ng_deepnegative_v1_75t` 는 **SD1.5 전용**이라 Illustrious·NoobAI·NAI 에서는 **파일이 없어 그냥 글자로 들어간다.** 긍정 프롬프트에 넣으면 반대 효과가 난다 |

## 10. 잠재 공간(latent space) 과 8의 배수
<small>⚠️ 2023-02 기준 · 근거 1건 · 자료 엇갈림</small>

**왜 해상도를 8의 배수로 잡으라고 하는가**에 대한 답이 여기 있다.

확산(diffusion)은 우리가 보는 픽셀 공간에서 일어나지 않는다.
VAE 인코더가 이미지를 **8배 압축한 잠재 공간(latent space)** 으로 밀어 넣고, 거기서 노이즈를 걷어낸 뒤, 다시 VAE 로 펼친다.
개인용 그래픽카드에서도 돌아가게 하려고 이렇게 만든 것이다.

```
512×512 이미지 ──VAE 인코더──▶ 4×64×64 잠재 ──확산(노이즈 제거)──▶ 4×64×64 ──VAE 디코더──▶ 512×512 이미지
```

| | 값 |
|---|---|
| 확산이 실제로 도는 공간 (SD1.5 기준) | **4 × 64 × 64** |
| 압축 배율 | **8배** — 잠재 1픽셀 = 실제 8픽셀 |

여기서 두 가지가 따라 나온다.

- **해상도는 8의 배수여야 한다.** 8 로 나누어떨어지지 않으면 잠재 격자에 딱 떨어지지 않는다
- **`latent` 업스케일러가 따로 있는 이유**도 이것이다 — 잠재 상태에서 키우느냐, VAE 로 펼친 뒤 이미지로 키우느냐의 차이다 → [업스케일과 화질](upscale.md)

> ⚠️ **원문 본문의 숫자는 틀렸다 — 댓글이 정정했다.**
> 이 설명을 담은 2023-02 글의 본문은 탐색 공간을 `3×512×512` 로 적고
> 경우의 수를 `256^(512×512×3) ≈ 10^1887436` 으로 계산했다(우주의 모든 원자 수가 약 10^82, 바둑의 모든 경우의 수가 약 10^768).
> **댓글이 `4×64×64` 로 정정했고, 8의 배수 규칙은 이 정정에서 나온다.**
> 본문의 큰 그림 — "이미지 생성 AI 는 그림을 만들어 내는 게 아니라 고차원 공간에 이미 존재하는 그림을 찾아내는 것" — 은 그대로 유효하다.
> 다만 정정은 **한 글의 댓글에서만 확인된 것**이다.

## 11. `PNG Info` 와 `Tagger` 는 다른 것이다
<small>2026-04 기준 · 근거 3건</small>

이 둘을 섞어 쓰는 질문이 채널에 반복해서 올라온다. **하는 일이 완전히 다르다.**

| | `PNG Info` | `Tagger` |
|---|---|---|
| 무엇 | 이미지 파일 안에 **박혀 있는 메타데이터**를 읽어 보여 준다 | 이미지를 **보고** 그 안의 요소를 태그로 **추출**한다 |
| 알 수 있는 것 | 어떤 모델·어떤 프롬프트·시드·스텝으로 뽑았는지 (**실제 값**) | 그림에 무엇이 있는지 (**추측한 태그**) |
| 메타데이터가 없으면 | **아무것도 못 한다** | 상관없다. 실사 사진도 된다 |
| 쓰는 때 | 남이 올린 png 의 설정을 그대로 알고 싶을 때 | 프롬프트 실마리를 얻거나 **로라 학습용 캡션**을 만들 때 |

**EXIF 보존** — PNG Info 로 볼 수 있는 것이 곧 이미지에 보존된 EXIF 다. 파일을 다른 형식으로 변환하거나 EXIF 를 지우고 업로드하면 사라진다.

### Tagger 의 threshold

| 도구 | 기본값 |
|---|---|
| DeepDanbooru (딥부루 분석) | `0.7 ~ 0.75` |
| WD 1.4 / WD14 Tagger | `0.35` |

**두 값이 다른 이유는 두 모델의 확신도 분포가 달라서**이며, 각각의 기본값 근처를 쓰는 게 맞다. 값이 낮을수록 태그가 많아지고, 높을수록 확실한 것만 남는다. 캐릭터 태그는 별도 threshold 를 두는 도구가 많다(기본 `0.85` 쪽).

WD14 Tagger 는 폴더째 분석해 이미지마다 `.txt` 로 저장하는 기능이 있어 **로라 학습용 데이터셋 캡션을 만들 때 그대로 쓴다.** → [로라 쓰는 법](lora-usage.md)

ComfyUI 에는 같은 일을 하는 `WD14 Tagger` 노드가 있고, Forge Neo 용은 `https://github.com/anxety-solo/sd-wd14-tagger` 가 정상 동작한다(eva02 large v3 모델이 기본 포함).

## 13. 태그 사전 — 이름을 몰라 못 찾는 것들

## 14. ⚠ AI 가 설명한 용어는 틀릴 수 있다 — 실제로 정정된 것 둘
<small>⚠️ 2025-07 기준 · 근거 3건 · 자료 엇갈림</small>

용어를 LLM 에게 물어 정리한 채널 글들이 남아 있는데, **그 안에 실제로 틀린 설명이 섞여 있었고 댓글이 잡아냈다.**
용어집에 이 항목을 두는 이유는 **같은 종류의 오류를 알아보게 하기 위해서**다.

### `NMKD` 와 `DAAM` 은 병합 기법이 아니다

2023-02 에 빙(Bing)에 들어간 ChatGPT 베타로 개념을 정리한 글에서, 댓글이 잡아낸 것이다.

> **'모델 병합 기법으로 NMKD 또는 DAAM 을 쓰라' 는 답변은 틀렸고, 되묻자 챗봇이 스스로 정정했다.**

| 이름 | 실제로 무엇인가 |
|---|---|
| **NMKD** | 로컬에서 도는 **GUI 프로그램 이름** (`NMKD Stable Diffusion GUI`) |
| **DAAM** | 프롬프트의 각 단어가 화면 어디에 작용했는지 보여 주는 **어텐션 히트맵 시각화 도구** |

작성자 본인이 적은 교훈이 정확하다 — **인터넷에 원문이 하나뿐이거나 아예 없는 정보는 LLM 이 자주 틀린다.**
DAAM 을 실제로 어떻게 쓰는지는 [프롬프트 쓰는 법](prompting.md) 의 daam 히트맵 실측 항목에 있다.

### 컨디셔닝은 U-Net 이 하는 것이 아니다

2022-11 의 Latent Diffusion 개념 설명글에서, '컨디셔닝을 프롬프트와 U-Net 으로 하는 것이냐' 는 질문에 붙은 정정이다.

| 부품 | 하는 일 |
|---|---|
| **조건 인코더 τ(θ)** | 프롬프트 · semantic map · i2i 이미지 같은 **조건을 임베딩 벡터로 만든다 — 컨디셔닝은 이쪽이다** |
| **U-Net** | τ(θ) 가 낸 벡터를 각 층에서 **cross-attention** 으로 받아 이미지 도메인을 바꾸거나, 잠재 벡터 `zT` 와 합쳐 **디노이징**을 한다 |

전체 구조가 VAE 형태라는 점 자체는 맞다.

### 왜 굳이 노이즈를 섞는가

같은 글에서 나온, 지금도 유효한 설명이다.

> 그냥 암기시키면 **평범한 복제만** 하지만, 답이 정해지지 않은 상태를 복원하게 만들면
> 모델이 **헤매는 과정에서 '새로운 것' 을 만들어 낸다.**

댓글의 GAN 대비 정리 — **정해진 레시피대로만 디코딩하는 것이 GAN, 레시피에 노이즈를 뿌려 변형시키는 것이 디퓨전**이다.
그래서 `denoising strength` 를 올릴수록 원본에서 멀어진다.

> ⚠️ 이 두 정정은 각각 **한 글의 댓글에서만 확인된 것**이다. 다만 정정 내용 자체는 논문 구조와 도구의 실제 정체에 부합한다.

### LLM 이 만든 '태그 사전' 도 같은 종류다

2025-07 에 ChatGPT 로 만든 **NSFW 태그 사전(약 120개, 태그 + 한글 설명 표)** 이 채널에 올라왔다.
글쓴이 스스로 '단부루에 있는 것만 뽑아 달라고 했는데 다 되는 건지는 모르겠다' 고 적었고, **댓글이 이를 확인해 줬다.**

> `collar`, `omorashi` 같은 항목은 **설명이 실제 단부루 태그의 뜻과 다르다.**
> 이 목록보다 **단부루의 태그 그룹(tag group) 문서**를 보는 게 낫다.

목록 안에도 `oral sex` · `anal sex` · `69 position` · `boob grab` · `butt grab` · `intercourse` 처럼
**일상 영어를 태그처럼 적어 둔 항목**이 많은데, 실제 단부루 표기는 `oral` · `anal` · `sixty-nine` · `breast grab` · `ass grab` 이다.

**교훈은 위 두 사례와 같다 — LLM 이 정리한 낱말은 분류 체계(어떤 범주로 나눠 생각할지)까지만 믿고,
문자열 자체는 반드시 단부루에서 검색해 존재와 게시물 수를 확인한다.**
