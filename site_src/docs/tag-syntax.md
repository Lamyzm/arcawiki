# 태그 문법 — 모델마다 다르다

> **결론부터.** 같은 의도를 쓰는 방법이 모델 계열마다 전부 다르다.
> 남의 프롬프트를 그대로 붙여넣으면 안 되는 이유가 여기 있다.
> 이 문서는 "내 모델에서 무엇을 쓸 수 있나"만 가른다.

---

## 한 장 요약

| | **ANIMA** | **Illustrious / WAI** | **NoobAI** | **NAI** |
|---|---|---|---|---|
| 작가 | **`@이름`** | **`artist:이름`** | **`이름`** (접두사 금지) | `artist:이름` |
| 가중치 | `(태그:2)` — **크게** | `(태그:1.2)` — **1.5 넘기지 않음** | 〃 | **`1.2::태그::`** |
| 음수 가중치 | 없음 | 없음 | 없음 | **`-6::태그::`** |
| 등급 | **`safe`** | **`questionable`** | **`general`** | `rating:` |
| 연도 | `year2024` | **금지** | **`year 2024` 권장** | — |
| 랜덤 | `__와일드카드__` | 〃 | 〃 | **`\|\|A\|B\|C\|\|`** |

!!! danger "같은 SDXL 인데 공식 지침이 정면 충돌한다"
    **NoobAI 공식 매뉴얼**은 `artist:` 접두사를 **금지**한다 — `artist:wlop` ✗ / `wlop` ✓.
    그리고 `year 2024` 를 **권장**한다.

    **Illustrious 가이드**는 정반대다 — `artist:` 를 **필수**로 하고 `year 20xx` 를 **금지**한다.
    (단부루에서 이미 새해 축전용으로 쓰는 태그이기 때문)

    채널 실사용 집계는 `artist:` **139 대 15** 로 Illustrious 쪽을 따른다.

---

## 1. 작가 태그

### ANIMA — `@` 가 필수

```
@wagashi \(dagashiya\), (@zankuro:0.85)
```

> Anima 는 작가 태그를 입력할 때 **반드시 `@` 로 시작**해야 한다.

!!! tip "채널에서 검색할 때는 '골뱅이'로 찾아라"
    아카에서 `@` 를 쓰면 멘션이 걸린다. 그래서 채널 사람들은 **`골뱅이`** 라고 한글로 쓴다.
    이걸 모르면 ANIMA 로라 트리거가 검색에 거의 안 잡힌다.

### Illustrious / WAI — `artist:` 가 필수

```
artist:wlop, (artist:blue gk:0.9)
```

빼면 이렇게 된다.

> `yd_(orange_maru)` 를 `artist:` 없이 쓰면 **배경에 갑자기 오렌지가 하나 나오고**,
> `artist:lunch_(shin_new)` 를 없이 쓰면 갑자기 **식당에서 점심식사 하는 찐빠**가 터진다.

### NoobAI — 접두사를 붙이지 마라

> `by xxx`, `artist: xxx` 는 사용하지 않고, **단순히 `xxx` 만** 작성합니다.

> noob 이후로 `artist:` 프롬프트 잘 안 보이던 이유가 이거였구나

## 2. 가중치

### ANIMA 는 크게, SDXL 은 작게

| | 시작점 | 상한 |
|---|---|---|
| **ANIMA** | **`:2`** | **4 이상 남발하면 검은 화면** |
| Illustrious / WAI | 1.0 | **1.5 넘기는 일이 사실상 없음.** 작가는 0.3~0.5 |

ANIMA 가 둔감한 이유는 인코더 구조다 — qwen3 LLM 이 프롬프트를 통째로 인코딩해 평균을 낸다.

### NAI 는 문법 자체가 다르다

```
1.2::artist:이름::        가중치
-6::artist collaboration::    음수 — 밀어내기
```

> `{}`, `[]` 하나당 0.05 다. **제발 중괄호 쓰지 말고 직관적인 숫자 가중치를 써라.**

!!! danger "이름이 숫자로 끝나면 한 칸 띄어야 한다"
    `qys3` 처럼 끝이 숫자면 **`qys3 ::`** 로 공백을 넣는다.
    안 그러면 **그 뒤의 모든 태그에 가중치 3배**가 붙는다.

!!! warning "SDXL 에서 `2::태그::` 가 먹히는 것처럼 보이는 건 착각이다"
    `2::` 와 `::` 가 **노이즈로 소비되고 이름만 적용**된 것이다.
    `2` 를 지워도 결과가 같다는 것으로 검증됐다.

## 3. 등급 태그 — 네 계열, 네 표기

| 계열 | 표기 |
|---|---|
| **ANIMA** | `safe` · `sensitive` · `nsfw` · `explicit` |
| **NoobAI** | `general` · `sensitive` · `nsfw` · `explicit` |
| **Illustrious** | `general` · `sensitive` · **`questionable`** · `explicit` |
| **NAI** | `rating:` 접두 |

**세 번째 칸의 이름까지 다르다.** 남의 프롬프트를 그대로 옮기면 여기서 어긋난다.

!!! warning "Illustrious 는 등급 태그가 없으면 작가가 무효화된다"
    > 이 rating 4가지 중 **하나라도 안 들어가 있으면 작가 이름을 넣어도
    > 밍숭맹숭하게 나오는 경우가 있음**

!!! note "ANIMA 는 반대 방향의 주의가 필요하다"
    > Anima 는 상당히 음란해서 **안 야한 거 뽑고 싶으면 꼭 `safe` 태그**를 넣는 것이 좋음

## 4. 퀄리티 태그

### `score_N` 은 두 형태가 다른 모델이다

| 형태 | 어느 모델 | DB 건수 |
|---|---|---|
| `score_9_up` (접미사 있음) | **Pony V6 전용** | 5 |
| `score_8` (접미사 없음) | ANIMA · Pony | 31 |

**Illustrious·NoobAI 글 153건 중 `score_` 등장은 0건이다.** 거기서는 쓰지 않는다.

### 모델별 권장

| 모델 | 퀄리티 태그 |
|---|---|
| **ANIMA** | `masterpiece, best quality` + `score_7~8`. **전부 1 아래로 눌러 쓴다** |
| **NoobAI** | **`very awa`** + `masterpiece`. 미학 태그가 따로 있다 |
| **Illustrious** | `masterpiece`, `highres, absurdres`. **앞뒤 양쪽에 넣는다** |
| **NAI V5** | 프리셋 — Standard = `very aesthetic, masterpiece, no text` |

!!! warning "`very awa` 는 양날의 검이다"
    > `very awa` 사용 미사용은 좀 호불호일 듯. 저거 쓰는 순간 **이미지가 상당히 단일화됨**

!!! note "왜 눌러 쓰나"
    `score_9` 는 **번들번들한 AI 느낌**을 만들고, `masterpiece` 는 **NSFW 편향**이 있다.
    그래서 배포 워크플로우가 전부 `(score_8:0.65)` 처럼 1 아래로 눌러 둔 것이다.

    다만 이 값들은 **채널 본문에 0건**이고 배포 워크플로우 JSON 의 기본값이다.
    본문에서 확인되는 실제 사례는 `(highres, absurdres:0.8)` 뿐이다(5개 글).

## 5. 연도 태그 — 계열마다 정반대

| 계열 | |
|---|---|
| **NoobAI** | **권장.** `year 2024` · `newest`(2021~24) `recent`(18~20) `mid`(14~17) `early`(11~13) `old`(05~10) |
| **Illustrious** | **금지.** 단부루에서 이미 **새해 축전 태그**로 쓰고 있다 |
| **ANIMA** | `year2024` 형태로 사용 |

작가가 옛날 사람이면 `oldest` 를 쓰거나 연도 태그를 버리는 것도 방법이다.

## 6. 특수 태그

### `artist collaboration` — 최다 사용

특수 태그 중 채널에서 가장 많이 쓰인다(**75건**). 다인 캐릭터의 화풍 분열을 막는다.

| 계열 | 쓰는 법 |
|---|---|
| 로컬 (SDXL·ANIMA) | **네거티브**에 `artist collaboration` |
| **NAI** | **긍정 칸에 음수로** — `-6::artist collaboration::` |

!!! note "NAI V5 에서는 뒤집혔다"
    > 일단 악명높은 artist collaboration 은 **빼도 되겠네** …
    > `artist collaboration, solo artist` 빼도 4버전대처럼 캐릭터끼리 그림체가 달라지진 않는 것 같음

### ⚠ `banned artist` 는 노이즈다

실험글에서 *"AI 특유의 물거북 향이 빠진다"* 는 관찰이 나왔지만 댓글에서 반박됐다.

> 단부루에 이미지도 없고 학습할 때 굳이 그걸 태깅했을 리도 없으니
> **결론은 그냥 노이즈일 듯**

### 랜덤 — 계열마다 문법이 다르다

| 계열 | 문법 |
|---|---|
| 로컬 (Impact Pack) | `__폴더/파일명__` · `{a\|b}` · `{2$$a\|b\|c}` · `3#__wc__` |
| **NAI** | **`\|\|A\|B\|C\|\|`** — 앞뒤에 빈 칸을 두면 "안 나옴"도 후보가 된다 |

### 주석 — 모델 기능이 아니라 도구 기능이다

같은 ANIMA 라도 쓰는 도구에 따라 다르다.

| 도구 | 주석 |
|---|---|
| EasyUseAnima | `#` |
| 프롬프트 매니저 | `//` — **`/* */` 미지원** |
| NAI Helper | `##…##` |

## 7. 자연어를 어디까지 쓰나

| 모델 | |
|---|---|
| **ANIMA** | **문장이 통한다.** 208×304 저해상도에서도 프롬프트를 이행한다 |
| **Illustrious** | 긴 문장을 **토큰 길이로 잘라 태그처럼 취급**한다 — 문법 이해가 아니다 |
| **Z-Image** | 자연어 캡션이 기본. 한국어도 통한다 |
| **NAI V5** | 토큰 한도 1471. 따옴표로 감싸면 텍스트 렌더링 |

> 실제 ILXL 1/2의 자연어 인식 능력은 그리 좋은 편이 아님. **NoobAI V-pred 보다 한 수 아래**임.

## 8. 이스케이프

괄호가 이름에 들어 있으면 백슬래시로 감싼다. **모든 계열 공통**이다.

```
furina \(genshin impact\)
wagashi \(dagashiya\)
```

**밑줄은 쓰지 마라.**

> 밑줄을 사용하는 것은 공백을 사용하는 것과 다른 결과를 초래하며,
> 최악의 경우 **트리거 워드가 완전히 무효화**될 수 있습니다.

---

## 9. NSFW 태그 배치

성적 묘사 자체가 아니라 **배치 기법**이다.

!!! tip "NSFW 는 메인 프롬이 아니라 캐릭터 프롬에 넣는다"
    > 전체적으로 nsfw 들어갔을 때 **화풍이 박살나는 경우가 많음**
    > → `nsfw` 태그는 메인 프롬보다 **캐릭터 프롬에 넣는 게 그림체 오염이 더 적음**

`toon (style)` 같은 화풍 태그는 **nsfw 가 들어가는 순간 작동을 멈춘다.**

## 10. 옮길 때 확인할 것

남의 프롬프트를 내 모델로 가져올 때 순서대로 본다.

1. **작가 문법** — `@` / `artist:` / 접두사 없음 중 어느 것인가
2. **가중치 척도** — ANIMA 는 크게, SDXL 은 작게
3. **등급 태그** — 세 번째 칸 이름이 맞는가
4. **연도 태그** — Illustrious 면 빼야 한다
5. **`score_`** — Illustrious·NoobAI 면 쓰지 않는다
6. **음수 가중치** — NAI 전용. 로컬에서는 네거티브로 옮긴다
7. **단부루에 없는 표현** — `blurry Edge` 같은 것은 엉뚱하게 해석된다
