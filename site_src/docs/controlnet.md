# 컨트롤넷 — 구도·포즈 잡기

> **원문 31건 → 이 문서 하나** · 주장 64개 · 정리 2026-08-14

컨트롤넷(ControlNet)은 프롬프트로는 잡히지 않는 **구도와 포즈를 그림 바깥에서 지정**하는 장치다. 참조 이미지에서 뼈대·깊이·선화만 뽑아내 그걸 따르게 시킨다.

**주의 — 채널의 컨트롤넷 원리 자료는 2023년 2월에 몰려 있고 전부 SD1.5 용이다.** 지금 쓰는 SDXL·Illustrious·ANIMA 에서는 받아야 할 모델부터 다르고, **ANIMA 에는 오픈포즈 컨트롤넷 자체가 없다.** 원리 설명(전처리기 성격, 조절바 의미)은 세대가 바뀌어도 그대로 통하므로 앞쪽에 두었고, 뒤쪽에는 **멀티 컨트롤넷 · 뼈대 직접 만들기 · ComfyUI 자작 오픈포즈 노드(`<pose-이름:강도:시작:종료>`) · 여러 명 뽑을 때의 리저널 병행 · ANIMA LLLite · 딸깍 통합팩 설정**을 붙였다. 항목마다 적힌 시점(`as_of`)을 반드시 볼 것.

## 이건 언제 쓰는 것인가
<small>⚠️ 2023-02 기준 · 근거 2건</small>

프롬프트만으로 뽑으면 **포즈와 구도는 AI 마음대로** 나온다. 원하는 포즈가 있어서 i2i 에 원본을 넣고 디노이즈를 먹이면 이번엔 포즈가 변해 버린다. 컨트롤넷은 그 문제를 없앤다.

이럴 때 쓴다.

- 원하는 포즈·구도가 이미 정해져 있을 때
- 밑그림이나 낙서를 채색하고 싶을 때
- 완성된 그림의 틀은 두고 그림체·분위기만 바꾸고 싶을 때
- 건물·인테리어의 직선과 원근을 고정하고 싶을 때

**포토샵이나 블렌더는 없어도 된다.** 컨트롤넷에 사진을 집어넣기만 하면 자동으로 포즈를 추출하고 그 포즈 기반으로 그림을 만들어 준다. "겁먹고 안 하면 손해"라는 것이 원문의 표현이다(70014728, 2023-02).

컨트롤넷은 **체크포인트와 별개로 얹는 것**이라 모델 병합이 필요 없고, 다른 체크포인트와 섞어 써도 포즈가 틀어지지 않는다(69724880).

## 먼저 — 지금(2024~2026) 받아야 할 모델
<small>2026-05 기준 · 근거 3건</small>

아래 표부터 보고 시작하라. **2023년 글에 적힌 모델 링크는 SD1.5 용이라 지금 모델에서는 동작하지 않는다.**

| 지금 쓰는 모델 | 무엇을 받나 | 받는 곳 / 비고 |
|---|---|---|
| SDXL · Illustrious(ILXL) | 오픈포즈 | `https://huggingface.co/xinsir/controlnet-openpose-sdxl-1.0` — reForge · ILXL 동작 확인 |
| SDXL · Illustrious(ILXL) | union sdxl **(댓글 권장)** | `union sdxl` 로 검색. 하나로 여러 전처리기를 처리하고 노드 작성법도 함께 나온다 |
| SDXL · Illustrious(ILXL) | union 컨트롤넷 | `https://huggingface.co/xinsir/controlnet-union-sdxl-1.0/tree/main` 의 `diffusion_pytorch_model.safetensors` → `models\controlnet` |
| ANIMA | Anima-LLLite | **오픈포즈 컨트롤넷 자체가 없다.** LLLite 를 컨트롤넷 대신 쓴다 |

- xinsir 오픈포즈 저장소에는 `diffusion_pytorch_model` 과 `diffusion_pytorch_model_twins` 두 개가 들어 있다. **차이는 밝혀지지 않았고 ILXL 에서 둘 다 정상 작동**했다(122545929, 2024-11, reForge 검증). 같은 저장소에 depth, canny 등 다른 모델도 있다.
- 오픈포즈가 둘 다 안 먹힌다면 컨트롤넷 가중치를 조정해 보라는 것이 댓글 답변이다.
- **ANIMA 는 SDXL 과 구조가 달라 기존 컨트롤넷이 전혀 호환되지 않는다.** kohya-ss 의 Anima-LLLite 가 그 자리를 대신하고, 글쓴이 권장값은 `strength 0.8 / start_percent 0.0 / end_percent 0.4` 다. strength 1.0 을 전 구간에 걸면 컨트롤넷이 그림을 놓지 않아 부자연스러워진다. **LLLite pose 는 preview3 학습이라 사실상 못 쓴다**(171458536, 2026-05). → [ANIMA](anima.md)

## 포즈를 안 따라갈 때 — 현행 대처 순서
<small>2025-12 기준 · 근거 2건</small>

ComfyUI + ILXL 에서 오픈포즈 이미지를 넣었는데 **따라하는 시늉만 하고 안 따라가는** 증상의 대처다(156251545, 2025-12).

1. **로라 개수를 줄인다.** 로라를 많이 쓰면 이 일이 생긴다. 개수를 줄이거나 찐빠를 내는 원인 로라를 찾아내라. → [로라 쓰는 법](lora-usage.md)
2. **오픈포즈 이미지의 구도에 결과물을 맞춘다.** 오픈포즈가 full body 구도이면 (a) full body 에 어울리는 비율을 고르고 (b) 모델이 추천하는 latent 크기로 오픈포즈 이미지를 리사이즈하고 (c) 프롬프트에 `full body` 태그를 넣는다.
3. 손이 계속 찐빠나면 **손이 없는 오픈포즈**를 쓴다.

글쓴이 스스로 "확률은 높아졌지만 100% 따르게 하지는 못했다"고 인정한 팁이며, 원리는 확실치 않다고 밝혔다.

같은 원인이 2023년에도 지적됐다 — **포즈 추출용 입력 이미지와 출력 해상도의 가로세로 비율이 안 맞는 것이 가장 흔한 실패 원인**이다. 가로가 긴 포즈 이미지에 세로로 긴 출력을 걸면 포즈가 화면 끄트머리에서 잘려 나가 생뚱맞은 이미지나 괴물이 나온다(70014728). 참고로 `Canvas Width/Height` 는 Scribble 모드의 그림판 크기이지 출력 해상도가 아니다 — 샘플링 방법 아래의 가로·세로를 만져야 한다.

## 전처리기 성격 표 — 무엇을 받고 무엇을 고를 것인가
<small>⚠️ 2023-02 기준 · 근거 2건</small>

전처리기 10종을 실제 결과물로 비교한 자료다(69724880, 2023-02, 추천 92). **SD1.5 시절 글이지만 각 전처리기의 성격은 SDXL/Illustrious 용에서도 같다.**

| 전처리기 | 하는 일 | 언제 고르나 |
|---|---|---|
| **Pose (OpenPose)** | 관절 뼈대를 추출 | 포즈 지정. 위치는 잡는데 거기 뭐가 들어갈지는 모르는 듯한 결과가 나오므로 **관련 프롬프트로 보강**한다 |
| **Depth** | 깊이맵. **캐릭터 깊이는 뭉뚱그리는 대신 배경 뎁스까지 계산** | 배경을 포함한 전체 깊이가 중요할 때 |
| **Normal** | 노멀맵. **배경을 무시하고 캐릭터 깊이를 Depth 보다 더 깊게** 계산 | 캐릭터 표현이 중요하고 배경은 날려도 될 때 |
| **HED** | 부드러운 외곽선 | **그림의 전체 틀을 깨지 않고 분위기만 바꿀 때** |
| **Canny** | 날카로운 외곽선 | **캐릭터 디테일이 중요할 때. 밑그림 채색 용도로는 성능이 압도적** (원래 없던 요소가 추가되는 문제는 있다) |
| **MLSD** | 둥근 것을 다 무시하고 **직선만** 딴다 | 캐릭터용이 아님. **건물·인테리어·빌딩** |
| **SEG** | 영역을 색상으로 분류 | 배경 요소를 살릴 때. SEG 색상 코드를 알아야 해서 번거롭다 |
| **SCRIBBLE / INTERACTIVE / FAKE** | 낙서를 그럴싸하게 | 8은 밖에서 그린 것, 9는 프로그램 안에서 그리는 것, 10은 AI 가 임의로 낙서한 뒤 다시 뽑는 것 |

실험 결과의 구체 예: **Depth 는 배경의 물병을 살렸지만 얼굴 안쪽 안경이 사라졌고, Normal 은 물병이 사라졌지만 안경이 표현됐다.**

글쓴이 총평은 "8, 9번 빼고 다 쓸 만하다". 댓글의 전문가 지적으로 **MLSD 와 SEG 는 배경 위주로 학습돼 씹덕짤을 소화하지 못하니 디테일한 이미지 생성에는 부적합**하다는 보완이 붙었다.

주의: **HED 와 Canny 에 일반 사진을 넣으면 그림이 이상해진다.** 사진→그림 변환이 아니라 **이미 완성된 그림이나 밑그림을 변환하는 용도**다.

## 조절바 세 개의 의미
<small>⚠️ 2023-02 기준 · 근거 2건</small>

컨트롤넷 패널에서 가장 헷갈리는 슬라이더 세 개다(69987661, 2023-02).

| 조절바 | 의미 | 만지는 기준 |
|---|---|---|
| **Weight** | 컨트롤넷 분석 결과를 결과물에 **얼마나 충실히 반영**할지 | 뎁스맵은 정확한데 포즈 재현율이 떨어지면 이걸 살살 조절한다 |
| **`○○○ resolution`** (Annotator resolution 등, 전처리기마다 이름이 바뀐다) | **중간 정보 이미지(뼈대·뎁스맵·선화)의 해상도** | 높을수록 참고 이미지가 선명해지지만 **무조건 높다고 결과가 좋진 않다.** 용도별로 여러 값을 실험 |
| **low / high threshold** (Canny 등에서 활성화) | 원본에서 **어디까지 인식해서 처리할지 = 인식 범위** | 인식 결과가 원했던 것보다 과다·과소하면 조절. 원본마다 매번 다르므로 기본값으로 쓰다가 마음에 안 들면 만진다 |

원문 글쓴이가 "본인의 경험과 통밥을 토대로 작성했으며 실제 원리와 다를 수 있다"고 명시한 글이다.

그 밖에 —
- **리사이즈 모드**: 뭘 골라도 어설프니 애초에 출력 width/height 를 컨트롤넷 입력 이미지와 맞추는 편이 낫다. Outer Fit 은 무조건 확대, Inner Fit 은 레터박스로 비율 유지, **Just resize 는 그림이 찌그러지므로 고르지 말 것**(69816884).
- **Low VRAM**: VRAM 8GB 이하면 체크. 6GB 에서도 컨트롤넷 low vram 옵션을 켜면 돌아간다는 보고가 있다(70014728 댓글).

## 뉴비가 실제로 막히는 지점
<small>⚠️ 2023-02 기준 · 근거 2건</small>

70014728(2023-02, 추천 69)이 Q&A 로 정리한 것 중 지금도 유효한 것만 추렸다.

**뼈대 이미지를 직접 넣을 때는 `Preprocessor: none` + `Model: openpose`.**
`Preprocessor = None` 은 **이미 만들어진 뼈대·뎁스맵을 직접 넣을 때**, `Preprocessor 설정` 은 **사진에서 추출할 때**다. 뼈대를 넣어 놓고 Model 에 canny 를 세팅하면 당연히 안 된다.

**검은 선으로 직접 그린 포즈는 안 된다.** 오픈포즈는 **관절의 숫자와 컬러가 정해져 있기 때문**이다. 그림판에서 사람 모양으로 선을 그어 넣어도 인식하지 않는다.

**오픈포즈는 실제 사람 사진용이다.** 사진은 타율이 좋지만 **그림은 타율이 낮거나 아예 인식을 못 한다.** 그림은 일단 넣어 보고 추출이 안 되면 **depth 나 normal 로 바꿔 쓰면 된다.**

**openpose 를 쓸 거면 openpose 모델을 받아야 한다.** canny 모델만 받아 놓고 포즈가 안 된다고 하면 안 된다 — 모델별로 하는 일이 다르다(69816884).

**포토샵·블렌더로 뼈대를 직접 만드는 사람이 있는 이유**: 사진에서 추출하면 간혹 관절이 증발한다. 15·17번 정보가 증발한 채로 돌리면 포즈는 잘 나와도 **얼굴이 붕괴될 확률이 높다.** 팔·다리 관절이 증발해도 마찬가지다. 직접 조절하면 이 문제가 없고 여러 명을 그릴 때도 효과가 좋다. 다만 **WebUI 확장 포즈 에디터가 나온 뒤로는 굳이 포토샵을 만질 필요가 없다**는 것이 원문의 결론이다.

**img2img 탭에서 오류가 난다면** 컨트롤넷에만 이미지를 넣고 img2img 쪽에는 안 넣어서다. i2i 기능이 필요 없으면 txt2img 탭에서 돌리면 된다(txt2img 의 컨트롤넷에도 이미지 칸이 있다).

## Canny 를 제대로 쓰는 법
<small>⚠️ 2023-02 기준 · 근거 3건</small>

Canny 를 그냥 쓰면 **배경·눈·머리카락의 쓸데없는 선까지 다 따 버려서** 원래 그림의 향이 짙게 남고 **몇몇 프롬프트를 무시하게 된다**(70685830, 2023-02).

절차 —

1. 배경을 대충 지운다(포토샵 빠른 선택 도구. 댓글: ABGRemover 같은 배경 제거 도구도 가능).
2. Canny 를 돌려 선화를 뽑는다. 허깅페이스 스페이스에서도 되지만 느리므로 **로컬에서 뽑는 게 낫다.**
3. **나온 선화에서 쓸모없는 선을 전부 지운다. 이목구비 포함.** 선이 없으면 AI 가 알아서 그려 주므로 얼굴에 집착하지 않아도 된다.
4. 정리한 선화를 넣고 **Model canny** 로 두고 Weight 를 조절해 가며 돌린다.

한계(댓글): 캐니로 선을 따 줘도 **기타 현 같은 가는 직선은 여전히 똑바로 못 긋는다.**

## 컨트롤넷을 여러 개 겹치기 — 멀티 컨트롤넷
<small>⚠️ 2023-02 기준 · 근거 4건</small>

컨트롤넷 하나로는 **한 가지만** 고정된다. 포즈만 잡으면 옷의 윤곽이 흐트러지고, 윤곽만 잡으면 자세가 어긋난다.
**형태·윤곽·자세를 각각 다른 방식으로 동시에 고정하려면 컨트롤넷을 여러 개 겹친다.**

**A1111** — 확장을 업데이트하면 `Settings` 에 항목이 생긴다.

```
Settings → Multi ControlNet: Max models amount (requires restart)
```

여기서 개수를 올리고 **WebUI 를 재시작**해야 반영된다(확장 기능 탭에서 '업데이트 확인' → 적용 후 UI 재시작, 프로그램을 완전히 껐다 켜는 편이 낫다). **최대 10개**까지 지정할 수 있다.

**ComfyUI** — `ControlNet` 노드를 여러 개 이어 붙이는 것이 같은 일이다. 별도 설정이 없다.

### 실제로 쓰인 조합과 강도

| 조합 | weight | 무엇에 썼나 | 시점 |
|---|---|---|---|
| `canny` + `hed` | 각 **0.3** | 3D 스크린샷을 2D 그림으로 변환 | 2023-03 |
| `canny` + `hed` + `depth` | 각 **0.6**, Guidance Start 0 / End 1 | 32프레임 영상 루프백 | 2023-03 |
| `depth` + `canny` (+ `openpose`) | — | 형태·윤곽·자세를 따로 고정 | 2023-02 |
| `openpose` + `depth` + `lineart` | — | 손·인체 삑사리 방지 3중 구조 | 2025-11 |

**강도 감각(3D→2D 변환 실측)** — canny+hed 조합에서 weight `0.3~0.4` 가 적정이고, `0.2` 로 내리면 형태가 완전히 딴판이 되거나 인체가 망가지며, `0.4~0.6` 으로 올리면 원본(3D)의 형태가 그대로 남는다. 여러 개를 겹칠수록 개별 weight 는 낮게 잡는 것이 요령이다.

## 뼈대를 직접 만들기 — magicposer · 포즈 에디터 · Blender
<small>⚠️ 2023-02 기준 · 근거 2건 · 자료 엇갈림</small>

**먼저 알 것 — 대부분은 직접 만들 필요가 없다.** 컨트롤넷에 사진을 집어넣기만 하면 전처리기가 알아서 포즈를 추출한다. 블렌더나 포토샵을 배워야 한다고 겁먹고 안 하면 손해다.

그래도 직접 만들어야 하는 이유는 하나다 — **사진에서 추출하면 관절이 간혹 증발한다.** 예를 들어 15·17번(얼굴 쪽) 정보가 빠진 채로 돌리면 포즈는 잘 나와도 **얼굴이 붕괴될 확률이 높다.** 팔·다리 관절이 증발해도 마찬가지고, 여러 명을 그려 넣을 때는 차이가 더 크다.

### 순서대로 — 쉬운 것부터

| 방법 | 설치 | 언제 |
|---|---|---|
| **magicposer** `https://webapp.magicposer.com/` | 없음 (웹) | 간단한 포즈. 채널의 사실상 표준 답 |
| 기존 포즈집 이미지 | 없음 | 마음에 드는 포즈가 이미 있을 때 |
| WebUI 확장 포즈 에디터 `https://arca.live/b/aiart/70174220` | 확장 | 관절을 직접 집어 옮길 때 |
| 포토샵 `https://arca.live/b/aiart/69959869` · 클립스튜디오 `https://arca.live/b/aiart/70005122` · PPT `https://arca.live/b/aiart/69978900` | 각 프로그램 | 이미 그 프로그램을 쓰고 있다면 |
| **Blender** `https://arca.live/b/aiart/69916661` | 무겁다 | 전처리기가 못 잡는 복잡한 포즈, 여러 명, 애니메이션 |

**Blender 글의 작성자 본인이 맨 앞에 정정을 붙여 두었다** — 컨트롤넷 기본 openpose 전처리기 성능이 생각보다 좋아서, 간단한 포즈라면 magicposer 같은 사이트나 포즈집 캡처를 넣고 preprocessor 를 `openpose` 로 두면 뼈대를 잘 따 준다. 블렌더는 전처리기가 자동으로 못 잡는 복잡한 포즈에만 쓰면 된다. 댓글도 같은 결론이다.

### Blender 로 갈 때

1. `https://www.blender.org/` 에서 설치
2. 애드온 `https://toyxyz.gumroad.com/l/ciojz` — **금액란에 0 을 쓰고 Purchase 하면 무료**
3. 편집 - 환경설정 - 애드온 탭에서 `rig_tools.zip` 설치 후 'Auto-Rig Pro Tools' 체크
4. 파일 - 열기로 `Openpose_bone_01.blend`
5. 오브젝트 모드에서 `Shift+A` 로 카메라 추가
6. 씬 컬렉션의 OpenPoseBone 옆 사람 아이콘을 누르고 상단 모드를 **포즈 모드**로 바꿔 파츠를 회전·이동
7. **넘패드 0** 으로 카메라 시점에 들어가 구도를 맞추고 `F12` 렌더 → 이미지 저장

조작: 휠클릭+드래그 = 시점 회전 / 휠 스크롤 = 거리 / `Shift`+휠클릭+드래그 = 위치 이동. 화살표가 드래그로 안 움직이면 `Ctrl` 을 누른 채 끈다.

## ComfyUI 자작 오픈포즈 노드 — 포즈를 프롬프트 문법으로 쓰기
<small>2026-05 기준 · 근거 2건</small>

오픈포즈의 실무적 불편은 두 가지다 — **포즈와 프롬프트를 둘 다 따로 지정해야 해서 귀찮고**, 켜 놓고 자고 일어나면 **밤새 똑같은 포즈만** 나와 있다.

채널 이용자가 만든 ComfyUI 커스텀 노드(`ComfyUi_NakoNode`)는 이것을 **프롬프트 문법**으로 바꿔 놓았다. 포즈를 프리셋으로 저장해 두면 로라처럼 텍스트로 불러 쓴다.

```
<pose-InAir>                   프리셋 InAir 의 포즈와 ControlNet 이 함께 적용된다
<pose-프리셋이름:강도:시작:종료>
<pose-reze:1:0:40>             reze 포즈를 강도 1 로, 0% 에서 시작해 40% 에서 종료
<pose-이름:1:0.4:0.7>          (리저널 노드 쪽 표기 — 시작·종료를 0~1 비율로)
```

이러면 **와일드카드로 포즈와 프롬프트를 다채롭게 조합**해 돌릴 수 있고, 강도·종료 수치만 바꿔 같은 포즈의 변주도 늘릴 수 있다. `<pose-제목>` 은 포즈 에디터의 enable 과 무관하게 강제로 컨트롤넷을 발동시킨다.

### 기능 넷

| 기능 | 하는 일 |
|---|---|
| 포즈 받아오기 | 외부 전처리 노드에서 포즈를 가져온다 |
| 포즈 에디터 | 가져온 포즈를 손으로 고친다 |
| 포즈 프리셋 | 고친 포즈를 이름 붙여 저장 |
| 포즈 컨트롤넷 | 프리셋을 불러 컨트롤넷으로 적용 |

**전처리 노드가 따로 필요하다** — `dwpose tensorrt` 를 권한다(가장 제대로 된 정보를 가져온다). 다만 **일반 dwpose tensorrt 노드에는 openpose json 출력이 없어서** 작성자가 개조한 판을 받아 `ComfyUI-Dwpose-Tensorrt` 내용물에 덮어써야 한다. 대안으로 `ultimate openpose estimator` 는 json 출력이 있고 감지 설정값을 조절해 인식률을 더 올릴 수 있지만 tensorrt 엔진 빌드가 필요하다.

**왜 에디터가 필수인가** — 사진과 달리 애니메 그림은 포즈 인식이 엉망인 경우가 많다. 에디터 조작은 `Ctrl+Z` / 휠 줌 / `Space`+드래그로 캔버스 이동 / `Shift` 클릭·드래그로 다중 선택이며, 여러 명이 있을 때 편집이 섞이지 않도록 **한 번에 한 캐릭터만 수정하게 하는 `select` 버튼**이 있다. 저장하면 현재 보이는 배경이 프리뷰로 함께 저장되고(배경이 없으면 뼈대 그림), 같은 이름으로 저장하면 덮어쓴다.

`comfyui-custom-scripts`(pysssss)가 깔려 있으면 포즈 태그 자동완성이 되는데, **새로 만든 포즈는 브라우저를 새로고침해야** 자동완성에 반영된다(노드 쪽은 다시 읽기 기능이 있다).

**설치 초기 오류(해결됨)** — 초기 버전은 `__init__.py` 20번째 줄의 importlib 호출 경로 문제로 로드에 실패했다. 상대 경로로 고쳐져 패치됐다.

## 여러 명을 뽑을 때 — 컨트롤넷만으로는 안 되고 리저널과 같이 써야 한다
<small>2026-05 기준 · 근거 4건</small>

두 명 이상을 뽑을 때 흔한 착각이 **'컨트롤넷으로 포즈를 두 개 잡으면 두 캐릭터가 나오겠지'** 다. 반은 맞다.

> **컨트롤넷만 쓰면 사람은 두 명 나오지만 특성을 먹이기 힘들어서 리저널과 같이 써야 한다** (자작 노드 제작자 답변)

반대 방향도 마찬가지다. 리저널 프롬프트(화면을 영역으로 나눠 영역별 프롬프트를 먹이는 것)만 쓰면 **캐릭터 위치가 시드마다 랜덤이라 마스크와 실제 위치가 어긋나 특성이 이상하게 섞인다.** 그래서 2023년 Latent 방식 글에서도 이미 **'영역이 완전 독립이라 AI 가 알아서 배치해 주지 않으므로 컨트롤넷 openpose 를 반드시 함께 써서 캐릭터를 영역 안에 잡아 둬야 한다'** 고 못박았다.

### 붙이는 법 두 가지

**방법 1 — 시드 고정 + 트레이싱 (컨트롤넷 없이)**
글로벌 프롬프트만 KSampler 에 직결한 채 원하는 구도가 나올 때까지 돌려 **시드를 고정**하고, 그 이미지를 이미지 로드 노드에 붙여 밑그림을 보며 트레이싱하듯 마스킹한다. 그다음 글로벌을 제외한 각 리저널에 '조건(타임스텝 범위)' 노드를 붙여 **시작 0.2 / 종료 1.0** 으로 맞춘다(초반 구도는 글로벌이 잡고 이후 디테일만 리저널이 맡는다). 색 차이가 크면 한계가 있다 — 원본이 흰 드레스일 때 빨간 드레스는 잘 안 입혀지고 초록색은 잘 된다.

**방법 2 — ControlNet openpose (타율이 상당히 높다)**
2D 포즈 에디터로 뼈대를 만들어 이미지 미리보기로 구운 뒤 이미지 로드 노드에 넣고, **뼈대를 보며 마스킹**한다. 포즈를 강하게 주면 창의성이 죽으므로 컨트롤넷 강도를 약화시키고 타임스텝 범위는 지운다.

### 실전 값

| 항목 | 값 | 이유 |
|---|---|---|
| 조건 영역설정 | **`default`** | `mask bound` 는 마스크 영역만 칼로 도려낸 것처럼 적용해 이질감이 심하다 |
| 타임스텝 범위 | 시작 `0.2` / 종료 `1.0` | 초반 구도는 글로벌, 이후 디테일은 리저널 |
| `bootstrap_steps` | **2** | 5~6 은 분리가 과해 그림 두 장처럼 보인다. 2 면 분리하되 자연스럽게 합성된다 |
| 컨트롤넷 포즈 타율 | 약 **8할** | 일반 리저널로는 거의 불가능한 구도도 나온다 |

**남는 한계** — 캐릭터가 너무 붙으면 영역이 겹쳐 **눈 색이 다른 캐릭터 색으로 오염된다.** 그리고 타율의 진짜 관건은 노드가 아니라 **ILXL 이 지원하는 구도·자세·행동 태그를 정확히 적는 것**이고, 그게 안 되면 두 명이 아니라 한 명이 '반반치킨' 이 된다.

**더 간단한 길(댓글)** — 두 명 이상 뽑는 게 목적일 뿐이라면 **ANIMA 를 쓰는 편이 낫다.** 컨트롤넷이나 리저널 없이도 잘 뽑아 준다. 다만 ANIMA 는 LoRA 가 안 먹히므로 창작 캐릭터 LoRA 를 쓸 거면 이 방법이 필요하다. → [ANIMA](anima.md)

## ANIMA 의 컨트롤넷은 다르다 — LLLite, 그리고 오픈포즈가 없다
<small>2026-07 기준 · 근거 3건</small>

**ANIMA 에는 우리가 아는 컨트롤넷이 없다.** 대신 `LLLite` 라는 다른 방식을 쓰고, **가장 많이 찾는 openpose 는 사실상 못 쓴다.**

> LLLite pose 는 preview3 학습이라 효과가 약하고, **ANIMA 용 오픈포즈 컨트롤넷은 없다**(댓글 확인).

받는 곳: `https://huggingface.co/kohya-ss/Anima-LLLite/resolve/main/anima-lllite-any-test-like-v2.safetensors`

`comfyui_controlnet_aux` 의 **AIO Aux Preprocessor** 로 조건 이미지를 만들어 `Apply Anima ControlNet-LLLite` 에 물린다.

### 모델카드가 학습했다고 밝힌 5종과 대응 전처리기

| 학습된 것 | 써야 하는 전처리기 |
|---|---|
| HED scribble | `FakeScribblePreprocessor` |
| PiDiNet scribble | `Scribble_PiDiNet_Preprocessor` |
| lineart | `Managa2Anime_LineArt_Preprocessor` |
| Grayscale A·B | `ImageRGBToYUV` 의 Y 출력 |
| (언급 없는데 잘 먹힘) | `DepthAnythingV2Preprocessor` |

`resolution` 에는 출력 이미지의 **짧은 변** 값을 넣는다(1024x1536 이면 1024).

### 강도 — 1.0 전 구간은 쓰지 마라

```
strength 1.0 / start 0.0 / end 1.0   → 컨트롤넷이 그림을 놓지 않아 부자연스럽다 (완전 복제용)
strength 0.8 / start 0.0 / end 0.4   → 글쓴이가 실제로 쓰는 값
strength 0.7 ~ 1.0                   → 창의성이 남는 범위
```

근거가 되는 경험칙: 생성 구간의 **0~30% 가 전체 구도, 30~70% 가 큰 디테일, 70~100% 가 마감**이다. 컨트롤넷은 구도만 잡고 빠지면 된다는 뜻이다.

### 두 가지 함정

- **모델 경로가 바뀌었다(댓글 정정)** — ComfyUI 업데이트 후에는 `model/controlnet` 이 아니라 **`model/model_patches`** 로 옮기고 '모델 패치 로더' 노드를 연결한 뒤 `R` 키로 노드를 갱신해야 한다.
  옛 워크플로우를 그대로 열면 이 오류로 죽는다 — **`Required input is missing: model_patch`**.
  `Apply Anima ControlNet-LLLite` 가 **커스텀 노드에서 ComfyUI 내장 노드로 바뀌면서 `model_patch` 입력이 새로 생겼기** 때문이다.
  ⚠ **파일을 옮기고 연결했는데 이번엔 strength 자리에 파일명이 들어간 채 NaN 으로 뜨고 `Failed to convert an input value to a FLOAT value` 가 난다면,
  값을 손으로 고치지 말고 그 노드를 삭제한 뒤 새로 불러와 재연결한다** — 구버전 워크플로우의 위젯 배치가 새 노드 정의와 어긋나 값이 밀려 들어간 것이다.
  임의로 `1.0` 을 넣으면 에러는 없어도 결과가 어색하거나 레퍼런스와 무관한 이미지가 나온다 → [오류 해결](troubleshooting.md)
- **최적화 노드와의 순서** — `모델로드 → LLLite → sageattention → block compile → KSampler`. 컨트롤넷을 쓸 때는 **SPEED 는 빼고 spectrum 만** 쓴다. → [VRAM·속도 최적화](vram.md)

미리보기가 답답하면 설정 > 실행(라이브 미리보기 방식)을 `default` → `latent2rgb` 로 바꾼다.

캔버스형 도구(프롬프트 매니저3)에서는 프리프로세서 레이어가 감지되면 **ComfyUI 설정 → Prompt Manager** 에 지정해 둔 ANIMA 컨트롤넷 모델을 쓰므로, **인페인팅용·영역지정용 모델을 미리 지정해 둬야** 한다.

## 오픈포즈는 앞구간에 건다 — 다만 스케줄러에 달렸다 (2025-11 실험)
<small>2025-11 기준 · 근거 1건</small>

오픈포즈의 **strength(강도)** 와 **적용 구간(start/end percent)** 이 실제로 어떻게 작동하는지, 같은 프롬프트로 값만 바꿔 가며 확인한 실험이다 (2025-11, Euler A / SGM Uniform).

| 설정 | 결과 |
|---|---|
| 강도 0.25 + 구간 0.25 (둘 다 낮게) | **거의 영향이 없다** |
| 강도 0.25 + 구간 0~100% | 포즈가 **흐릿하게만** 반영되고 실제로는 다른 자세가 많이 나온다 |
| 강도 1 + 구간 **0.75~1 (뒷부분)** | **여전히 상관없는 자세가 많이 나온다** |
| **강도 1 + 구간 0~0.25 (앞부분)** | **자세를 확실하게 따라간다** |

**해석** — 오픈포즈는 **초반 디노이즈 과정에 강하게 관여**하고, 앞에서 형태가 잡히면 뒷부분은 알아서 채워진다.
따라서 **뒷구간에 아무리 강하게 걸어도 이미 정해진 구도를 바꾸지 못한다.**

**권장** — 프롬프트와 오픈포즈가 서로 영향을 주며 생성되길 원한다면 **strength 1 또는 0.75 에 구간 0~0.25 근처**에서 조정한다.

### ⚠ 다만 이 결론은 스케줄러에 달렸다 (댓글)

> **`simple` 이나 `lcm` 처럼 초반에 후딱 끝내는 스케줄러는 초반에만 집중해도 되지만,
> `karras` 같은 스케줄러는 꾸준히 줘야 한다.**

글쓴이는 **Euler A + SGM Uniform 으로만** 돌렸다. 다른 스케줄러를 쓴다면 구간 값을 그대로 가져오지 말고 자기 스케줄러 기준으로 다시 잡아야 한다.

이 문서 앞쪽의 '조절바 세 개의 의미' 와 [ANIMA](anima.md) 의 LLLite 강도 권장값(구간 0~0.4)도 같은 이야기를 다른 각도에서 하고 있다.

## Deep Shrink 와 함께 쓰기, 그리고 계열이 안 맞을 때
<small>2026-02 기준 · 근거 2건</small>

**Deep Shrink 와 컨트롤넷은 기본적으로 호환되지 않는다.**
(Deep Shrink = 샘플링 초반에 잠재 해상도를 줄였다 되돌려 고해상도 생성에서 구도가 무너지는 것을 막는 기법.)

`controlnet deep shrink patch` 라는 wrapper 노드를 사이에 끼우면 함께 쓸 수 있다.

| | |
|---|---|
| 선행 노드 | `https://github.com/kinfolk0117/ComfyUI_GradientDeepShrink` — ⚠ **그중 advanced 노드와만 호환되므로 일반 버전과 함께 쓰면 안 된다** |
| 입력 | 컨트롤넷 파일 + 샘플러에 넣던 모델 |
| 아래 텍스트창 | Deep Shrink 가 관여하는 **스텝과 해상도 변형 배율**. deep shrink advanced 에 쓰던 텍스트를 그대로 옮긴다 |
| 쓰는 상황 | 제작자 말로는 **단일 샘플링으로 1700x1700 이상** 가려면 반필수 |

*(배포 방식이 특이하다 — 본문 첫 이미지를 새 창으로 열어 '다른 이름으로 저장' 한 뒤 확장자를 zip 으로 바꾸면 노드 파일이 나온다. 한 글에서만 소개됐다.)*

### ⚠ 계열이 안 맞는 컨트롤넷을 물리면 — `mat1 and mat2`

SDXL·포니 계열 모델에 `control_v11p_sd15_lineart` 처럼 **SD1.5 용 컨트롤넷**을 물리면 이 오류가 난다.

```
when executing KSampler: mat1 and mat2 shapes cannot be multiplied (308x2048 and 768x320)
```

**모델과 같은 계열의 컨트롤넷을 써야 한다** — 파일명에 `sd15` 가 들어가면 SDXL 에서 못 쓴다.
(같은 문구가 로라에서 나면 로라의 베이스 계열이 다른 것이다 → [오류 해결](troubleshooting.md))
