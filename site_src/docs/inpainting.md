# 인페인팅·아웃페인팅 — 고쳐 그리기

> **원문 80건 → 이 문서 하나** · 주장 129개 · 정리 2026-08-14

인페인팅은 **마음에 드는 그림의 일부만 다시 그리는 것**이고, 아웃페인팅은 **캔버스를 넓혀 바깥을 그려 넣는 것**이다. 둘 다 승부는 **디노이즈 강도 하나에서 갈린다.**

채널 자료는 2022년 A1111 실측부터 2026년 ComfyUI·ANIMA 까지 4년에 걸쳐 있고, **2026년에는 '인페인팅 전용 컨트롤넷'이 나오면서 판이 한 번 바뀌었다.** 그래서 값 표와 현행 방식을 앞에 두고, 옛 A1111 실측은 근거로 뒤에 남겼다.

문서 뒤쪽에는 **고쳐 그리기 말고 다른 손질**을 모았다 — SAM3 자동 마스킹 워크플로우, 편집 프로그램 레이어 기초, 누끼, 모자이크, 마스크가 없는 웹 서비스에서의 우회, NAI 캔버스 편집 도구.

## 이건 언제 쓰는 것인가
<small>⚠️ 2025-05 기준 · 근거 2건</small>

**"마음에 꼭 드는데 한 군데가 아쉬운 그림"에만 쓴다.** 이게 원문의 결론이다(66068091, 2022-12, 추천 51).

인페인트로 하는 일 —

- 손·손가락 찐빠 수정
- 잡티·워터마크 같은 필요 없는 요소 삭제
- 원래 없던 것 추가(바보털, 소품, 배경 요소)
- 표정만 바꾸기
- 옷 갈아입히기

**작업량이 결코 적지 않다.** 인페인트를 할 바에는 t2i / i2i 에서 가챠를 더 돌리는 편이 나은 경우가 많다는 것이 원문의 현실적 조언이다. 인페인트도 결국 가챠다.

핵심 원리 하나만 기억하면 된다 — **인페인트는 그림을 따로 얹어 주는 게 아니라 주변 환경에 동화시켜서 그려 준다.** 그리고 **AI 는 내가 지정한 범위가 무슨 의미인지 알 턱이 없다**(135530946, 2025-05). 이 두 문장에서 이 문서의 마스킹 규칙이 전부 나온다.

## 디노이즈 값 표 — 이게 전부다
<small>2026-04 기준 · 근거 9건</small>

**디노이즈 강도가 전부다.** 0 이면 원본과 차이 없고, 1 이면 원본을 참고하지 않고 처음부터 그린다.

**용도별 실측값** (66068091, 2022-12, A1111 실사용):

| 하려는 일 | 디노이즈 | 왜 |
|---|---|---|
| 없던 것을 새로 만들기 (바보털 추가) | **1.0** | 완전히 새로운 것이니 원본을 참고하면 안 된다 |
| 필요 없는 요소 삭제 (사람귀 지우기) | **1.0** | |
| 잡티 제거 | **0.6** | |
| 인페인트한 흔적 지우기 | **0.15** | 원본을 거의 유지하고 싶으므로 |
| 손이 그렇게 나쁘지 않을 때 손 수정 | **0.4** | |
| 손가락이 머리카락과 융합됐을 때 | **0.5** + 네거티브에 `fused hair + finger` | |
| **뭘 할지 모르겠을 때 시작값** | **0.75** | 여기서 시작해 배치 4로 보고 조절 |

**단계별 감각** (168734715, 2026-04, WebUI + Illustrious XL 기준. 원문 그대로):

```
최대한 기본 유지 > 0.5 > 적당히 변경 > 0.7 > 거의 원본 변형 > 1.0
```

**밑그림이 있을 때의 규칙** (60495270, 2022-10, X/Y Plot 실측): 칠하려는 부분의 **밑그림이 자세하거나 원화 위에 그리는 것이면 0 에 가깝게**, **아무렇게나 그렸거나 밑그림이 아예 없거나 크게 수정하려면 1 에 가깝게**. 마우스로 대충 그린 밑그림은 **0.5~0.75 구간**에서 가장 잘 살아난다 — 1.0 에서는 밑그림의 길이도 색도 무시하고 프롬프트대로만 그린다.

곁다리로 알아 둘 것: **디노이즈를 작게 잡을수록 실제 스텝 수가 줄어들어 처리가 빨라진다**(60495270, 공식 툴팁).

### 자동 얼굴 보정(ddetailer·디테일러)의 디노이즈

| 목적 | denoise | 근거 |
|---|---|---|
| **원래 얼굴을 유지한 채 다듬기** | **0.2 전후** | 2023-03 대문대회 출품작이 실제로 쓴 값 (72242457). 얼굴 보정 도구는 이 정도로 아주 낮게 줘야 원형이 유지된다 |
| 얼굴을 바꿔도 될 때 | 0.4~0.5 | 그만큼 원본에서 멀어진다 |

### 수정과 i2i 를 번갈아 할 때는 점점 낮춘다

2023년 고퀄 작업의 표준 패턴은 **0.55 → 0.5 → 0.3** 으로 내려가며 수정과 i2i 를 번갈아 하는 것이었다 (72250546).
업스케일 체인에서도 같다 — **해상도를 크게 올릴수록 없던 물체가 구석에 생기므로 단계마다 디노이즈를 낮춘다**(마지막 단계에서 0.15, 73207701).
→ [업스케일과 화질](upscale.md)


### i2i 소스별 디노이즈 상한 — 소스가 그림에 가까울수록 올릴 수 있다

위 표가 **'무엇을 하려는가'** 로 값을 정한다면, 밖에서 가져온 이미지를 i2i 에 넣을 때는 **'소스가 무엇인가'** 가 상한을 정한다.
2023년 대회 출품작 셋의 실측이다.

| i2i 소스 | 디노이즈 상한 | 근거 |
|---|---|---|
| **실사 자료 사진** | **0.2 ~ 0.3** — 이보다 올리면 **전혀 다른 그림**이 된다 | 72250414 |
| **3D 게임 스크린샷** | **0.35** (사이버펑크 2077 스샷 → 애니 화풍, SD Upscale) | 73280389 |
| **애니메이션 캡처** | **0.47** (원피스 캡처 → 화풍 변경, 768x512) | 72444635 |

**규칙은 하나다 — 소스가 이미 그림에 가까울수록 디노이즈를 올릴 수 있다.**
실사 사진은 형태를 유지한 채 화풍만 바꾸는 것이 목적이라 0.3 이 벽이고, 이미 애니메이션인 캡처는 0.47 에서도 원본 구도와 인상이 유지된다.

72250414 는 같은 글 안에서 **소스마다 값을 달리 준 것**이라 특히 참고가 된다 — ControlNet depth 용으로 짜깁기한 신문은 디노이징을 조금 높이고,
나머지 자료 사진 두 장은 0.2~0.3 사이를 오갔으며, **마지막 마감 SD Upscale 은 0.1** 로 걸어 글자를 일부러 살짝 뭉갰다.

→ 업스케일러 계열이 정하는 **하한**은 [업스케일과 화질](upscale.md) 의 '⚠ 업스케일러 계열이 디노이즈 하한을 정한다' 항목에 있다.

## 마스킹 — 넓고 단순하게 잡아라
<small>⚠️ 2025-05 기준 · 근거 4건</small>

초보가 가장 많이 하는 실수는 **대상 모양에 딱 맞게 타이트하게 마스킹하는 것**이다.

**실패 사례**: 들판에 꽃을 넣고 싶어서 꽃 모양으로 딱 맞게 마스킹하고 태그에 `flower` 를 넣었더니 안 나온다. 이유 — **온 세상 꽃이 다 그렇게 생기지 않았으므로 AI 에게는 그냥 타이트하고 기괴한 범위 지정일 뿐이다**(135530946).

규칙 —

- **무에서 유를 창조할 때는 단순하고 넓은 범위로 마스킹한다.** 그러면 나온다.
- **눈만 칠하면 어떤 표정인지, 손만 칠하면 어떤 포즈인지 모른 채 생성해 버린다.** 주변 두어 곳에 작게 점을 찍어 마스킹하면 그 지점까지 잘라내므로 참조 범위가 생긴다. **모든 인페인트에 해당하는 원칙**이다(98883845).
- **디노이즈 0.8 이상을 줄 때는 원본보다 마스크를 더 넓게** 잡아라. 공간이 모자라 예쁜 손이 마스크 범위를 넘어 잘려 나오면 눈물 난다(66068091).
- **요소를 지울 때도 대상보다 넓게** 마스킹해야 헤어스타일이 자연스럽게 나온다.
- ComfyUI 라면 `Grow Mask With Blur` 의 expand 를 **15~30** 으로 올린다. 마스크를 너무 타이트하게 따면 그림자·살 눌림 같은 원래 흔적이 남아 어색해진다(168110618).

반대로 **마스킹 영역 밖으로는 그려지지 않는다.** `large breasts` 처럼 형태를 키우고 싶으면 마스크 영역을 먼저 넓혀야 한다(168110618).

## 실전 요령 — 배치 4, 샘플러, 색 이상
<small>⚠️ 2022-12 기준 · 근거 1건</small>

66068091(2022-12) 하나에서 나온 것들이지만 채널 인페인트 글 중 가장 상세하고, UI 가 조금 바뀌었을 뿐 방법론은 그대로 통한다.

**배치 사이즈 4 로 돌려라.** 인페인트는 애초에 타율이 높지 않고, **4장의 결과 경향을 보고 디노이즈를 조절하기 위해서**다. 조절 절차:

```
기본값 0.75 로 4배치
 → 아예 망가진 게 있다  → 원본을 더 유지해야 함 → 0.6
 → 여전히 망가진다      → 과감히 0.4
 → 유지는 됐는데 안 지워졌다 → 0.4 초과 0.6 미만
```

4장이 애매하면 값을 안 바꾸고 가챠를 반복하는 것도 방법이다.

**인페인트에 원본과 같은 샘플러를 쓸 필요가 없다.** 예시에서 원본은 `DPM++ 2M Karras` 였지만 인페인트는 `Euler a` 로 했고 결과가 같은 느낌이었다(좁은 범위일 때. 넓은 범위를 인페인트하면 샘플러 특유의 느낌이 묻는다). **결과가 안 나오면 샘플러를 바꿔 보는 것도 효과적**이다.

**t2i 에서 '인페인트로 보내기'** 를 누르면 프롬프트·이미지·샘플링 수·폭·높이가 자동 입력된다. 단 **샘플링 방식과 CFG 는 계승되지 않고, 시드는 계승된다.**

**인페인트 부분만 누렇거나 뿌옇게 나올 때** — (1) 설정에서 **색보정(원본 색 보정) 켜기** (2) **VAE 켜기**. 하나만 켜도 되고 둘 다 켜도 된다. VAE 를 안 쓰는 사람에게는 색보정이 유효하다.

**마스크한 부분이 검게(김처럼) 나올 때** — 그 그림은 뭘 해도 검게 나온다. t2i 로 돌아가 시드를 고정하고 **중요도가 낮은 프롬프트의 가중치를 0.01 수준으로만 바꾼다**(예: `(sunflower:1.2)` → `(sunflower:1.19)`). 거의 같은 그림이 나오는데 이걸로 인페인트하면 검게 안 나온다.

프롬프트는 언제 건드리나: **추가하고 싶은 게 있으면 넣고, 없애고 싶으면 지운다. 단순히 수정만 하는 것이면 안 건드린다.**

## 로컬 현행 — 인페인팅 전용 컨트롤넷이 판을 바꿨다
<small>2026-04 기준 · 근거 4건</small>

2026년 로컬에서 인페인트를 제대로 하려면 **인페인팅 전용 컨트롤넷을 물리는 것이 표준**이다. 디노이즈를 세게 줘도 경계가 깨지지 않는다는 것이 핵심 이점이다.

| 쓰는 모델 | 인페인팅 컨트롤넷 | 받는 곳 / 넣는 곳 |
|---|---|---|
| NoobAI · Illustrious 계열 | NoobAI Inpainting ControlNet | `https://civitai.com/models/1376234/noobai-inpainting-controlnet` → `models/controlnet` |
| ANIMA | Anima-LLLite inpainting v2 | `https://huggingface.co/kohya-ss/Anima-LLLite/resolve/main/anima-lllite-inpainting-v2.safetensors` |

**NoobAI 인페인팅 컨트롤넷** (162809080, 2026-02) — 이 컨트롤넷이 요구하는 입력은 "수정할 부분을 **순수한 검정색으로 채운 이미지**"다. `comfyui_controlnet_aux` 의 `Inpaint Preprocessor` 노드를 불러와 `black_pixel_for_xinxir_cn` 을 `true` 로 바꾸면 마스킹한 부분이 자동으로 검정으로 채워진다.

> **디노이즈를 1.0 까지 올려도 일관성이 깨지지 않고 자연스럽게 수정된다. 마스킹을 러프하게 대충 해도 경계가 자연스럽게 이어진다.**

컨트롤넷 없이 denoise 0.8/0.9/1.0 으로 돌리면 경계면 이질감이 확연한데, 물리면 같은 디노이즈에서도 깔끔하다. 이름은 NoobAI 용이지만 **Illustrious 기반 모델에서도 정상 작동**한다.

**한계 — 사실상 2D 전용이다.** 인페인팅 컨트롤넷이 NoobAI 로 학습돼 있어 flat color · anime coloring 계열에서 잘 먹고 **반실사·실사로 갈수록 타율이 급락한다.** 피규어 사진 실험에서는 컨트롤넷을 안 쓴 것과 동등하거나 그 이하였다(168110618 댓글, 작성자 재확인).

**ANIMA LLLite 인페인팅** (171376566, 2026-05) — `Apply Anima ControlNet-LLLite` 노드로 물리면 **LLLite 없이는 0.7 이상에서 깨지던 경계가 유지된다.** ComfyUI 업데이트 후에는 모델 파일을 `controlnet` 이 아니라 **`model_patches` 폴더로 옮기고 `ModelPatchLoader` 노드를 연결해야** 동작한다(댓글 정정).

**참고 — WebUI 딸깍 인페인트의 한계**: 168734715 본문은 WebUI 에서 얼굴을 칠하고 디노이즈만 조절하는 방식을 소개하지만, 댓글에서 "딸깍으로는 한계가 분명해서(머리 갈라지는 부분에 억지로 머리가 생겨 부자연스러운 틈이 생김) **로컬에서 알잘딱하려면 NoobAI 인페인팅 전용 컨트롤넷을 쓰는 것이 맞다**"는 지적이 붙었다. 이 항목이 그 대답이다.

## ComfyUI 노드 구성 — VAE Encode + Set Latent Noise Mask
<small>2026-05 기준 · 근거 3건</small>

ComfyUI 에서 인페인트 노드를 직접 엮을 때의 정답이다.

**`VAE Encode (for Inpainting)` 을 쓰지 마라. `VAE Encode` + `Set Latent Noise Mask` 를 써라.**
전자는 **마스킹 주변부가 깨진다**(예시에서 다리 왼쪽 마스킹 주변이 깨졌다). 댓글에서도 "인페인트 안 한 부분 색상이 어두워지는 현상"이 이 워크플로에는 없는 이유를 latent noise mask 차이로 답했다(170890690, 2026-05).

연결 순서:

```
이미지 로드[이미지] → VAE 인코드[픽셀 이미지]
VAE 인코드[잠재]   → 노이즈 마스크 설정[잠재]
이미지 로드[마스크] → 노이즈 마스크 설정[마스크]
                    → KSampler[잠재]
```

**이건 2023년에 이미 문제로 지적됐다.** `VAE Encode (for Inpainting)` 은 "원본 그림 크기와 지정 영역 크기에 따라 적정 세팅이 천차만별이라 간편히 쓰기에 부적합하다"는 것이 2023-09 글의 평가였고, 그때의 대안은 Impact Pack 의 Detailer 샘플러였다(86146682). **2026년의 대안이 Set Latent Noise Mask 다.**

**MaskEditor 조작** — 이미지 노드 우클릭 → `Open in MaskEditor`. 마우스 휠 위아래(또는 Thickness 바)로 브러시 크기, **좌클릭 마스킹 / 우클릭 지우기**, Clear 로 전체 지우기, `Save to Node` 로 확정(86146682). 결과가 흐릿하게 겹쳐 보이면 **마스킹 브러시 투명도를 1 로 되돌려라**(171376566 댓글).

## 그림을 합성해 넣기 — 반만 덮어 3분할
<small>2026-04 기준 · 근거 2건</small>

프롬프트만으로는 안 나오는 것을 넣는 방법이다. **로라 없이 뽑기 어려운 것**에 특히 쓸모 있다.

절차(135530946, NAI 기준이지만 로컬도 같다) —

1. 인터넷에서 원하는 그림(예: 장미 일러스트)을 받는다.
2. i2i 에 던지고 **strength 0.3~0.7** 로, 작가·퀄리티 태그를 제외한 나머지를 전부 밀어버린 채 돌린다 → 내 그림체로 변환된다.
3. 누끼를 딴다(NAI 배경 리무버, 포토샵, 배경 제거 사이트 아무거나. **대충 따도 된다**).
4. 원본 그림 위 원하는 위치에 얹는다.
5. **여기가 핵심 — 얹은 것을 다 덮어서 마스킹하면 안 된다.** 다 덮으면 AI 입장에서 남은 건 배경뿐이라 처음부터 그리는 것과 같아진다. **반 정도만 덮어서** 인페인트하면 AI 가 아래에 남은 장미를 보고 위에도 장미를 그려 주므로 배경과의 괴리감이 사라진다.
6. 위를 돌렸으면 아래도 반 정도, 맨 아래도. **3분할해서 위부터** 돌리기를 추천하며 디테일이 필요하면 4분할.

**소품을 따로 생성해 합성하는 경우**(167534946, 2026-04, ComfyUI + ANIMA) — 소품 프롬프트를 본 이미지 프롬프트에 그대로 합치면 분량이 늘어 **모델의 집중력이 분산되고 그림을 잡아먹는 찐빠**가 난다. 그래서 따로 뽑아 합성한다.

- `Inpaint Crop&Stitch` 로 녹여내며 `output_target` 을 **원본 소품 크기에 맞춘다.**
- **노이즈 제거량은 0.5 내외.** 너무 낮으면 안 녹고 너무 높으면 찐빠.
- 인페인트 프롬프트에는 평소 품질 프롬프트·로라 트리거 + **소품 생성에 썼던 긍정·부정 프롬프트**를 넣는다. 소품 설명이 없으면 찐빠 확률이 오른다.
- **업스케일을 합성보다 먼저 하는 편이 낫다** — 합성 후 업스케일하면 그 과정에서 찐빠가 난다(작성자 반성). → [업스케일과 화질](upscale.md)

## NAI 인페인트의 제약
<small>⚠️ 2025-05 기준 · 근거 2건</small>

**NAI 인페인트에는 strength(디노이즈 강도) 조절 자체가 없다**(135530946 댓글).

그래서 로컬처럼 "다 덮고 strength 를 낮춘다"는 방법을 쓸 수 없고, 위 항목의 **반절씩 나눠 돌리는 방식**이 그 자리를 대신한다.

우회로 — ComfyUI 에서 NAI 의 i2i 기능을 이용해 **강도 조절이 되는 인페인트+디테일러를 직접 구현한** 워크플로우가 채널에 있다(98883845, 2024-02).

- 동작: 마스킹 → 잘라내기 → 업스케일 → i2i → 다운스케일 → 원본에 병합. **사실상 디테일러와 같은 원리**다.
- 강도는 로컬 SD 와 비슷하게 **0.3~0.6** 사이에서 조절.
- 핵심 확장은 `ComfyUI_NAIDGenerator` 이고, **NAI 액세스 토큰을 ComfyUI 폴더의 `.env` 에 `NAI_ACCESS_TOKEN=토큰` 형식으로** 넣어야 한다(댓글).

## 아웃페인팅 — 캔버스 바깥 그려 넣기
<small>2026-02 기준 · 근거 3건</small>

**채널에 아웃페인팅 자료는 거의 없다.** 수치가 있는 글은 사실상 세 개뿐이라 셋을 모두 적는다.

**① ComfyUI (현행, 2026-02)** — 별도 아웃페인팅 모델이 필요 없다. 기본 노드 **`Pad Image for Outpainting`(아웃페인팅을 위한 이미지 패딩)** 으로 캔버스를 넓히고(예시는 양옆 512px), 넓힌 부분을 검정으로 채워 **인페인팅 컨트롤넷에 물리면** 된다. 프롬프트에는 `bed, room` 처럼 채워 넣을 배경을 적는다. 컨트롤넷 없이 같은 아웃페인팅을 하면 **성능 차이가 확실**하다(162809080).

**② A1111 (2022-10, 공식 권장)** — 위치는 img2img 탭 맨 아래 `Script` → `Outpainting mk2` 또는 `Poor man's outpainting`. 공식 문서의 권장 설정을 원문 그대로 옮기면:

> 그림과 맞는 좋은 프롬프트 + **디노이징과 CFG 스케일을 최대로** + **스텝 50~100** + **Euler ancestral 또는 DPM2 ancestral 샘플러**

아웃페인팅은 일반 생성과 달리 **스텝 수가 많을수록 크게 이득**이다. 글쓴이 채용값은 Euler A / 스텝 50 / 스트렝스 0.8(1660s 사양에 맞춤).

| Outpainting mk2 옵션 | 실험 결과 |
|---|---|
| Pixels to expand | 확장 크기. 상하좌우를 각각 선택 |
| Color variation | **원본에 따라 적정값이 다르다.** 컬러풀하지 않은 원본은 값이 올라갈수록 이상이 생겼고, 컬러풀한 원본은 0/0.5/1 모두 정상 |
| **fall-off exponent** | **최대값 4 일 때 가장 좋은 디테일**(2, 0 과 비교) |
| Mask blur | 글쓴이도 모르겠다고 밝힘 |

**③ NAI — anlas 0 으로 캔버스 넓히기(편법, 2024-11)** — NAI 에는 아웃페인팅 기능이 아예 없다.

1. 확장할 그림을 i2i 베이스로 넣고 **스트렝스와 노이즈를 최소로** 만든 뒤 비율에 맞는 `small~~` 해상도로 바꾼다 → 작은 해상도의 똑같은 그림.
2. 그 작은 그림을 다시 i2i 베이스로 넣고 **해상도를 normal 로 올린다.** (normal = `portrait 832x1216` / `square 1024x1024` / `wide 1216x832`)
3. 캔버스에 빈 공간이 생긴다. 원본을 원하는 위치로 옮긴다.
4. **원본만 빼고 빈 공간을 전부 색칠**해 인페인트한다.

NAI 는 normal 해상도까지가 anlas 무료 구간이라 이 방법이 성립한다. 대신 해상도를 낮췄다 올리므로 **찐빠가 좀 날 수 있다.** 특히 여러 명을 뽑을 때 유용하다(121264790).

## SAM3 로 따내고 컨트롤넷으로 고쳐 그리기 — 현행 워크플로우
<small>2026-05 기준 · 근거 2건</small>

마스크를 손으로 칠하는 대신 **SAM3 로 대상을 자동으로 따내고**, 인페인팅 전용 컨트롤넷으로 그 부분만 다시 그리는 구성이다. 앞 항목의 '인페인팅 전용 컨트롤넷' 을 실제 워크플로우로 묶은 것이다.

### 준비

```
# 커스텀 노드 (ComfyUI 매니저에 없어 수동 설치)
cd ComfyUI\custom_nodes
git clone https://github.com/kohya-ss/ComfyUI-Anima-LLLite
```

| 모델 선택 | **원본과 같은 모델**을 쓸수록 타율이 오른다. 원본 모델을 모르거나 AI 그림이 아니면 **WAI** 가 평균 타율이 가장 높다 |
| 원본이 2500px 초과 | 이미지 확대 비율 노드의 **바이패스를 켜고** 배율을 조절 |
| 원본이 너무 작음 | Downscale 노드를 **바이패스로 끔** |
| 구도가 복잡함 | 상황이나 포즈를 프롬프트로 설명해 준다 |
| 엉뚱한 게 나옴 | **마스킹한 부분 외의 프롬프트까지 꽉 채워 넣으면 오히려 결과가 이상해진다** |

### 마스크 편집 노드

불안정하던 Mask painter 대신 Impact Pack 의 **`Preview Bridge (Image)`** 를 쓴다. 그림이 로딩된 상태에서 우클릭해 마스크 에디터를 연다.

```
restore_mask = if_same_size   다음 실행 때 같은 크기 이미지가 들어오면 이전 마스크가 남는다
restore_mask = never          매번 초기화
```

**`if_same_size` 는 내용이 달라도 크기만 같으면 마스크가 남는다.** 이전 마스크가 유령처럼 따라오면 이 스위치를 의심할 것.

1차 샘플러에서 여러 장을 뽑아 마음에 드는 것을 고르고 진행할 수 있게 돼 있는데(`1차 반복 횟수` 노드로 조절), **이후 디테일러가 한 번 더 밀기 때문에 선택 시점의 그림과 최종 결과는 다소 달라진다.** → [디테일러](detailer.md)

## 인페인팅으로 안 되는 것은 편집 프로그램으로 — 레이어 기초

## 배경만 지우기 — 누끼
<small>2026-06 기준 · 근거 2건</small>

캐릭터만 남기고 배경을 지우는 작업이다. 배경을 갈아 끼우거나 합성해 넣을 때 앞 단계가 된다.

WAN2.2 계열 **Bernini** 모델로 하는 ComfyUI 워크플로우가 이미지용·비디오용으로 공유돼 있다. 배경과 오브젝트가 섞인 부분(오토바이 유리창, 그림자)을 **반투명으로 구분**해 낸다.

**핵심 성질** — 원본 이미지를 마스크로 덮어씌우는 방식이라 **누끼가 안 된 부분은 원본과 픽셀 단위로 동일하다.** 그래서 반복 실행해도 열화가 없다.

|---|---|

| 값이 0 일 때 | 얼굴과 머리카락 경계를 외곽선으로 오인한다 |
| **반드시** | T2V 가 아니라 **I2V** 로 할 것 — T2V 는 이미지 보존 능력이 없어 편집 능력이 붕괴한다(댓글 정정) |

## 부분을 가리기 — 모자이크
<small>2025-11 기준 · 근거 2건 · **근거 약함**</small>

고쳐 그리는 것이 아니라 **가리는** 쪽이다. 채널 이용자가 만든 ComfyUI 커스텀 노드 팩이 있고 노드 경로는 `/Mosaic` 이다.

```
custom_nodes 폴더에 압축 해제 → pip install -r requirements.txt 를 한 번 실행
```

Detect 노드의 weight 는 실행 시 자동 다운로드되는데 **용량이 매우 크니 주의**하라고 작성자가 적었다.

### 무엇을 가릴 것인가 → 어떤 감지 모델을 쓰나

| 대상 | 쓰는 것 |
|---|---|
| 피부만 | Sapiens |
| 눈·코·입만 | Segformer Face. 단 segformer 는 face close-up 이어야 하므로 **face yolo 로 마스킹한 뒤** 적용 |
| 캐릭터 전체 | BiRefNet 또는 Yolo segment 의 person seg 모델 |
| 얼굴만 빼고 | 모자이크 이미지에 yolo seg 로 face 를 **Demosaic** |
| 여러 캐릭터 중 하나 | Yolo seg 로 person detecting 후 `select mask` (랜덤이면 `mask order` 를 random) |

`Mosaic` 노드는 image 와 mask 를 받는다. `mosaic size` 가 거칠기이고, `Pixelize mask` 를 true 로 하면 마스크 자체를 mosaic size 크기의 정사각형 집합으로 바꾼다. `Demosaic` 은 모자이크된 이미지의 일부를 원래대로 되돌린다(원본 이미지 연결 필요).

**크기를 일정하게 유지하려면** `Size guidance` 를 쓴다 — 예를 들어 얼굴 bbox 대각선의 `1/32` 크기로 모자이크하면 얼굴 크기가 달라도 비슷한 비율이 유지된다.

> **충돌 주의(작성자 스스로 경고)** — ComfyUI 는 커스텀 노드를 노드명으로만 구분하므로 `1038lab/ComfyUI-Mosaic` 과 **동시 설치하면 문제가 생긴다.** `1038lab/ComfyUI-RMBG` 와는 Yolo·Segformer·BiRefNet 노드 기능이 중복된다.

한 글에서만 나온 노드팩이고 댓글에 검증 보고가 없다.

### ⚠ 수동 마스킹은 seed 를 고정해야 한다

**마스킹은 '현재 이미지' 기준이라 이미지가 바뀌면 마스크가 초기화된다.**
그래서 직접 칠할 때는 **seed 를 `fixed` 로 고정**해야 한다.
요령: seed 를 `incremental` 로 두고 돌리다가 원하는 그림이 나오면 **시드를 1 뒤로 돌린 뒤 `fixed`** 로 바꾼다.

ComfyUI 안에서 모자이크를 넣는 두 갈래는 이렇다.

| | 노드 체인 | 장단 |
|---|---|---|
| **자동** | `Simple Detector` → `SEGS Filter` → `GrowMask` → 모자이크 | 알아서 해 준다 / **디텍터 모델 성능이 결과를 좌우** — 아예 못 잡거나 겨드랑이 같은 엉뚱한 부위를 잡는다 |
| **수동** | `Preview Bridge` 우클릭 → **Open in MaskEditor** | 실수가 없다 / 위의 seed 제약이 붙는다 |

- `GrowMask` 대신 **디텍터의 `bbox_dilation`** 값을 써도 같은 효과다.
- **`Blockify Mask`** 를 쓰면 마스크가 네모반듯해진다.
- `Preview Bridge` 의 **`if_empty_mask`** 를 설정하면 마스크가 없을 때는 아무 처리도 하지 않아, **원하는 이미지에만** 모자이크를 걸 수 있다.

필요한 커스텀 노드는 `KJNodes`, `Impact-Pack`(디텍터가 여기 있다), `ComfyUI-Mosaic` 셋이다.
작성자 권장은 **평소엔 자동, 마스킹이 엇나갈 때만 수동**으로 쓰는 혼용이다.

## 마스크를 못 쓰는 웹 서비스에서의 우회
<small>2026-05 기준 · 근거 1건 · **근거 약함**</small>

그록 같은 웹 이미지 편집 서비스에는 **인페인팅 마스크가 없다.** 게다가 선정적이라고 판단하면 아예 거부한다. 같은 효과를 손으로 내는 절차가 채널에 하나 올라와 있다.

1. 기존 그림에서 **문제가 될 부분을 포토샵으로 검은색으로 덮는다** (거부당하지 않게)
2. 그 상태로 서비스에 넣어 **헤어스타일만** 자기 캐릭터 것으로 바꾼다 — 프롬프트는 반복해서 굴린다
3. **액세서리는 프롬프트만으로는 안 된다.** 참고 이미지를 함께 넣고 간단한 프롬프트를 준다
4. 포토샵으로 돌아와 검은색으로 덮었던 부분을 지우고, 미세하게 뒤틀린 곳은 **지우개 도구의 강도를 최소로 낮춰** 살살 지우며 타협한다

요컨대 **'검열에 걸리는 영역을 가려 놓고 나머지만 AI 로 고친 뒤, 가렸던 부분을 수동으로 복구한다'** 는 것이다.

**한 글에서만 언급됐고 구체적인 프롬프트나 설정값은 없다.** 작성자 본인도 하루 5~10장씩 만들다가 지쳐서 그만뒀다고 덧붙였다. 로컬에서 마스크를 쓸 수 있다면 이 문서 앞쪽의 정공법이 훨씬 낫다.

## 먼저 칠하고 나서 인페인트한다 — 디노이즈를 낮추는 가장 확실한 방법
<small>⚠️ 2025-04 기준 · 근거 1건</small>

인페인팅의 가장 흔한 사고는 **"고치려던 것 말고 다른 게 바뀌는 것"** 이다. 원인은 대개 디노이즈가 높아서다.

> **깡 인페인트로 머리색을 바꾸려면 최소 0.6, 높으면 0.8 까지 올려야 한다.
> 그 정도 디노이즈는 주변까지 변형시켜서, 없던 리본이 머리에 생기는 식의 사고가 난다.**
> **그런데 미리 색을 칠해 두면 0.5~0.55 로도 된다.**

즉 **그림 툴에서 원하는 색을 대충이라도 칠해 두고 낮은 디노이즈로 돌리는 것**이 핵심이다.
마우스로 긁는 수준이면 되고 그림 실력은 필요 없다.

| 방식 | 필요한 디노이즈 | 부작용 |
|---|---|---|
| 깡 인페인트로 색 바꾸기 | **0.6 ~ 0.8** | 주변까지 변형 — **없던 장식이 생긴다** |
| **미리 칠하고 인페인트** | **0.4 ~ 0.55** | 원본 변형이 적다 |

얻는 것이 셋이다 — ① **원하는 색에 가장 가깝게** 뽑을 수 있고, ② **디자인(패턴·기장)도 마음대로** 연출되며,
③ **낮은 디노이즈로 갈 수 있어 원본이 지켜진다.**

### Krita 로 밑칠하는 순서 (무료 툴)

1. 이미지를 불러오고 **먼저 레이어/마스크를 복제**해 사본만 표시한다.
2. 배경이 단순하면 영역선택 툴로 흰 배경을 클릭해 `Delete`, 지우개로 잔여물 정리.
   배경이 복잡하면 반대로 **대상을 선택**(Shift 클릭으로 누락분 추가)하고 점선을 우클릭 → 새 레이어로 복제하는 편이 빠르다.
3. 필요 없는 부분은 `Ctrl+Shift+A`(모두 선택 해제) 후 인접영역 선택 도구로 Shift 클릭해 한꺼번에 지운다.
4. **채색의 핵심은 '알파 잠금' 이다.**
5. 칠한 이미지를 인페인트에 넣고 **0.4~0.55** 로 돌린다.

> **알파 잠금** — 켜 두면 **투명 영역에 브러시가 번지지 않는다.** 막 칠해도 색이 밖으로 삐져나가지 않는다.
> 이것 하나가 "그림 못 그려도 된다" 의 근거다.

| 단축키 (Krita) | 하는 일 |
|---|---|
| `Ctrl` + 클릭 | 그 자리의 색을 **픽업** (살색을 집는다) |
| `K` / `L` | 집은 색을 **어둡게 / 밝게** — 검스·커스·흰스를 이걸로 만든다 |
| `B` | 브러시 / 지우개 전환 |
| `Ctrl+Shift+A` | 모두 선택 해제 |

덧칠 개념이라 고르게 펴 바르려면 **브러시를 크게 해서 한붓그리기 하듯 꾹 눌러** 전체를 칠한다.

### 지름길 — 배경 지우기는 손으로 하지 마라

> **배경 지우기는 Krita 대신 `Rembg`(누끼) 노드를 쓰면 잘 지워진다.** *(댓글)*

작성자도 본문에 보완을 달았다 — 워크플로우의 누끼 노드에서 미리보기 노드를 `save` 로 바꾸면
**캐릭터/배경 두 이미지가 저장되고**, 그 둘을 그림 툴에 레이어로 불러 작업할 수 있다.

*(2025-04, ComfyUI + NAI XL VPred1.0 2d Accel 환경의 실사용 기록이다.)*

## ⚠ '도자기 피부' 의 범인은 디테일러가 아니다 — 이 설명은 틀렸다
<small>⚠️ 2023-04 기준 · 근거 1건 · 자료 엇갈림</small>

> "피부와 얼굴이 도자기처럼 뭉개진다" 는 호소가 여러 건 올라왔고, **다들 디테일러를 범인으로 지목했다.**

단순 업스케일만 하면 이미지가 깨지므로 i2i 로 보정하는데, **그 과정이 질감을 지운다.**

### 대처

| 업스케일 denoise 를 **0** 으로 | **denoise 0 이어도 i2i 는 어느 정도 뭉갠다** |

| 실제로 통한 처방 |
|---|
| 업스케일 단계의 **denoise 를 0 대신 `0.1 ~ 0.2`** 로 준다 |

**실제로 한 사용자가 업스케일에서 디노이징을 살짝 주니 피부 질감이 돌아왔다고 보고했다.**

## 자동 인페인팅의 원리 — SAM + GroundingDINO (2023-04 교재)
<small>⚠️ 2023-04 기준 · 근거 3건</small>

지금은 SAM3 디테일러가 하는 일을, 2023년에는 A1111 확장 DDSD 가 했다.
**따라 할 일은 없지만 자동 인페인팅이 무슨 원리로 도는지 이해하기에는 이 시절 글이 가장 명료하다.**

### 두 모델이 하는 일

| 모델 | 하는 일 |
|---|---|
| **GroundingDINO** | `face` 같은 **단어**를 주면 그 대상을 **네모(바운딩박스)** 로 잡는다 |
| **SAM (Segment Anything)** | 이미지의 모든 것을 잘라 **마스크**로 만든다 |
| 둘을 합친 것 | Grounded-Segment-Anything → webui 확장이 `sd-webui-segment-anything` |

**즉 "글자로 부위를 지정하면 그 부위만 마스크가 잡혀 인페인팅된다" 가 자동 디테일러의 전부다.**
오늘날 SAM3 디테일러의 프롬프트 칸에 `face, eyes, hands` 를 적는 것과 완전히 같은 구조다.

### 세미콜론은 '동시' 가 아니라 '반복' 이다

DINO 토큰에 `face; eye; hair` 처럼 적으면 셋을 동시에 처리하는 게 아니라
**face 로 한 번, eye 로 한 번, hair 로 한 번 — 인페인팅을 세 번 반복**한다. 각 구간의 프롬프트도 세미콜론으로 나눠 적는다.

한 번의 탐색에서 마스크가 여러 개 잡히면(예: 얼굴 두 개) Bitwise 로 고른다.

| 옵션 | 결과 |
|---|---|
| `AND` | 겹친 부분만 |
| `OR` | 모두 합쳐서 한 번에 |
| `OTHER` | **마스크마다 따로 1회씩** 인페인팅 |

*(여러 명을 각각 처리하려면 `split mask` 체크를 해제하면 떨어져 있는 마스크마다 따로 인페인팅한다.)*

### 동작 순서 — 어디서 망가졌는지 추적하려면

```text
업스케일(택1) → 디테일러 → 업스케일(택1) → 후보정 → 워터마크
```

**이 순서를 알아야 "어느 단계에서 뭐가 망가졌는지" 를 좁힐 수 있다.**
바로 위 절의 '도자기 피부' 도 이 순서 덕에 범인이 업스케일 쪽 i2i 로 특정됐다.

### 순서를 지켜야 설치가 된다 (2023-04, 원리는 지금도 같다)

```text
1. 그래픽카드/토치 버전에 맞는 CUDA Toolkit 설치
2. 같은 버전 cuDNN 압축을 풀어 CUDA 설치 폴더에 덮어쓰기
3. 그 다음에야 확장 설치
4. 새로고침(reload)이 아니라 webui 를 완전히 껐다 켜기 → 라이브러리·모델 자동 다운로드
```

> **확장을 CUDA 보다 먼저 깔면 실패한다 — 확장 설치 시 CUDA 로 C++ 을 컴파일하기 때문이다.**
> 이미 그렇게 깔았다면 `webui/venv/lib/site-packages` 의 `groundingdino` 와 `segment_anything` 관련 파일을
> 전부 지우고 다시 실행해야 한다 *(댓글)*.
> `AssertionError: Extension directory already exists` 는 폴더가 남아 있다는 뜻이므로 `extensions` 폴더에서 수동 삭제.

### 같은 시절의 곁가지 — 구간마다 다른 모델 쓰기

**얼굴에 강한 모델로 얼굴만, 손에 강한 모델로 손만** 인페인팅하면 각 모델의 장점만 뽑아 쓸 수 있다.
지금 ComfyUI 에서는 흔한 구성이지만 당시 webui 에서는 드문 발상이었다.

| 비용·주의 |
|---|
| 중간중간 모델을 리로드하므로 **생성 시간이 크게 는다** (512x512 기준 한 장 약 1분) |
| **생성 도중 정지를 누르면 롤백되지 않아** UI 표시와 실제 로드된 모델이 어긋난다 |
| dino1~dino3 에 **같은 모델**을 지정하면 재로드가 생략돼 시간을 아낀다 |

그리고 순서에 관한 원칙 하나 — **인페인팅 결과는 원본 해상도에 좌우되므로
원칙적으로는 업스케일 후 디테일러를 돌리는 편이 품질이 좋다.** VRAM 이 모자라서 순서를 바꾸는 것이다.

## 잘라 확대해 다시 그리기 — 인페인트 디테일러 노드의 원리 (2024-11)
<small>⚠️ 2024-11 기준 · 근거 1건</small>

디테일러가 하는 일은 사실 인페인팅이다. **작은 얼굴이나 손을 크게 확대해 다시 그리면 디테일이 살아난다** 는 원리뿐이다.

```text
마스크 영역만 잘라 냄
  → 설정한 픽셀 수를 넘지 않는 선에서 확대
  → 디노이징
  → 원본 크기로 축소해 마스킹된 부분만 붙임
```

ComfyUI 에서 이 흐름을 노드로 짜면 이렇게 된다.

```text
Load Image  →  Masked Resize Image  →  (본인 샘플러)  →  Paste Masked Image
```

| 파라미터 | 뜻 |
|---|---|
| `blur_radius` | 마스킹 경계면 블러 강도 |
| `blur_expansion_radius` | 마스킹 영역 확장 (0~10). **기본값 그대로 써도 무방** |
| `max_resolution` | `1024x1024` / `1280x1280` / `1536x1536` 중 선택. ⚠ **비율이 아니라 "그 해상도의 총 픽셀 수를 넘지 않는 선에서 최대로 확장"** 이라는 뜻이다 |

NAI 와 함께 쓸 수 있게 픽셀 수를 **64의 배수**로 맞춰 준다. **NAI 로 인페인트할 때는 반드시 I2I 옵션을 써야 한다.**

인페인트 참조 범위를 넓히려면 **화면의 두 지점에 작은 점을 찍어 마스킹**하는 요령이 쓰인다 —
**참조 범위를 크게 잡으면 변형은 쉬워지지만 품질이 떨어진다** 는 맞교환이 있다.

표정을 바꾸려고 denoise 를 높이면 부자연스러워지는데, **NAI 사용자라면 Director Tools 의 Emotion 으로 표정을 바꾼 뒤
인페인트를 한 번 돌리는 편이 가장 잘된다** *(댓글)*.

*(2024-11 배포된 커스텀 노드 `Inpaint with Detailer` 기준. 설치는 `custom_nodes` 에 넣고 그 폴더에서 `python3 setup.py`.)*

## 밑그림을 만들어 합성하고 인페인트로 녹이기 — 3D 데생 인형 (2024-08)
<small>⚠️ 2024-08 기준 · 근거 2건</small>

프롬프트만으로는 **타율이 극히 낮거나 아예 만들 수 없는 체위·구도**가 있다.
그럴 때 쓰는 것이 "3D 데생 인형으로 자세를 만들어 그 스크린샷을 i2i·인페인트의 밑그림으로 쓰는" 방식이다.
**바로 위의 '먼저 칠하고 나서 인페인트한다' 와 같은 발상** — 밑그림을 만들어 두고 낮은 힘으로 돌린다.

### 네 가지 방식과 타율

| 방식 | 설명 | 현실 |
|---|---|---|
| **1. 하나씩 만들어 합성** | 캐릭터를 따로 뽑아 한 그림에 합성한 뒤 전체 인페인팅 | **의도한 동작대로 나올 확률이 가장 높다** |
| 2. 구도를 통째로 인페인트 | 스크린샷을 통째로 넣고 기대 | **15장 돌려 1장** 건졌다 |
| 3. 얼굴만 잘라 붙이고 인페인트 | | 세세한 동작이 무작위로 바뀐다 |
| 4. 2인을 t2i 로 뽑고 한 명 합성 | 3인 장면용 | |

⚠ **ComfyUI(로컬)로는 2·3번을 할 수 없어 1번 방식을 쓸 수밖에 없다**고 원문이 밝힌다(2024-08, NAI3 기준).

### 실사용 strength 값

| 단계 | strength |
|---|---|
| 디자인돌 포즈 → 몸체 뽑기 | **0.5 ~ 0.65** |
| 얼굴 따로 만들기 | 0.35 ~ 0.55 |
| 얼굴 인페인팅 (공식 일러 얼굴을 vibe 에) | **0.7** — 마음에 드는 결과를 다시 0.7 로 한 번 더 돌리면 품질이 올라간다 |
| 합성본 이질감 줄이기 | **0.3 ~ 0.55** (예시 0.35) |
| 마지막 전체 조율 | **0.12** |
| 구도 통째로(2번 방식) | 0.75 ~ 0.85 |

### 군더더기를 안 붙이는 요령

- **몸체만 뽑을 때는 캐릭터 이름·특징 프롬프트를 넣지 않는다.** 넣으면 머리카락·장신구가 딸려 붙는다.
- **알몸으로 뽑을 때 vibe 참조 이미지는 얼굴 정보만 든 그림**을 쓴다. 전체 일러를 넣으면 의상과 장식품이 따라온다.
- 옆모습이 필요하면 **참조 이미지도 옆모습**이어야 한다. 공식 일러는 정면뿐이므로 옆모습 장면을 먼저 생성해 얼굴을 추출한다.
- 배경은 `no humans` 로 따로 만들고, 캐릭터의 검은 배경을 지운 뒤 레이어로 얹는다. 가려지는 부위는 아예 지운다.

### '마이너 캐릭터' 판정

> **캐릭터 이름만 프롬프트에 넣고 돌렸을 때 특징이 정확히 재현되면 학습이 잘된 캐릭터,
> 이상하거나 특징이 안 나오면 마이너 캐릭터다. 마이너 캐릭터는 1번 방식 말고는 답이 없다.**

### 합성 티가 나는 두 원인

**합성 경계선**과 **그림체 차이**다. 몸체 아래에 검게 칠한 레이어를 깔아 외곽선을 살리고
색 혼합 툴로 농도를 조절하면 선 쪽 이질감이 준다.
고해상도로 돌릴 때는 **반드시 새 캔버스를 그 해상도로 만들어 그림을 붙여 확대해 맞춘 뒤 저장**해서 돌려야 인체 비율이 안 깨진다.

⚠ **Design Doll 은 라이선스(한화 약 10만 원)가 없으면 체형 변경도, 체형·자세 저장도 안 된다.**
댓글에서도 "과정을 생각하면 그냥 코이카츠로 뽑아 i2i 하고 싶어진다" 는 지적이 나왔고,
글쓴이도 **2인 장면은 코이카츠가 낫다**고 인정하면서 실사·반실사와 마이너 캐릭터에는 디자인돌이 낫다고 답했다.

## DDSD 로 배우는 자동 인페인팅의 문법 (2023, 지금은 대체됨)
<small>⚠️ 2023-05 기준 · 근거 3건</small>

**지금 그대로 쓸 일은 거의 없다** — ADetailer 와 ComfyUI 디테일러가 이 역할을 대신한다.
그래도 **'마스크를 말로 지정한다' 는 발상**은 지금의 SAM3 디테일러로 그대로 이어지므로, 문법을 보면 감이 잡힌다 (2023-04 · 2023-05).

### 마스크를 얻는 세 문법

| 문법 | 무엇 |
|---|---|
| `<area:left\|right\|top\|bottom\|all>` | **지역 마스킹** — 이미지를 절반씩 |
| `<file:파일명>` | `models/ddsdmask` 폴더에 넣은 **이미지를 마스크로** 쓴다. **확장자는 빼고 파일명만** 적는다. 크기와 무관하게 비율로 동작하므로 **비율이 다른 이미지를 쓰면 뭉개진다** |
| `<model:파일명>` | YOLO/mediapipe 모델. YOLO 는 첫 실행 때 `models/yolo` 에 자동 다운로드되며 그 폴더의 파일명을 적는다. **mediapipe 는 파일이 아니라 내부 동작이라 `<model:face_media_full>`, `<model:face_media_short>` 둘뿐** |

세 문법 모두 공통 옵션이 붙는다.

```text
<type1:type2:dilation:confidence>
dilation   = 마스크를 얼마나 부풀릴지
confidence = model 타입에서만 쓰이는 탐지 민감도
```

**조합도 된다** — `person AND <model:face_yolov8n>` 처럼 쓰면 원래 DDetailer 가 하던 '얼굴만 탐색' 을 구현할 수 있다.
탐색 프롬프트는 `face`, `hand` 처럼 부위 단어를 적으면 되고 `a woman face` 같은 문장형도 인식률이 높으며, **비워 두면 DINO 자체를 건너뛴다.**

### 박스 처리 순서까지 지정하는 개조판 (2023-05)

DINO 탐색 결과 박스의 처리 순서를 `from left` / `from right` / `size desc` / `size asc` / `overlap desc` / `overlap asc` 중에 고르고,
**몇 개를 칠할지와 몇 개를 건너뛸지(skip box)** 를 지정할 수 있었다. 그래서 **두 명 중 한 명의 얼굴만 다른 로라로 인페인팅**하는 응용이 가능했다.

> ⚠️ **제약** — `select box order` 가 `NONE` 이면 오리지널 DDSD 로 동작하고, **NONE 이 아니면 detect 프롬프트의 AND/OR 연산자와 `()` `[]` 우선 연산자가 동작하지 않는다.**
> 배포 링크는 we.tl 임시 공유라 **현재 전부 만료됐다.**
> 마스크가 어떻게 잡혔는지는 DDSD 설정의 **`Save dino mask images you are working on`** 을 켜서 직접 확인할 수 있다.

### 그 시절의 실전 감각 — 지금도 통하는 것

| | |
|---|---|
| Upscaler 를 켜면 | 이미지를 타일로 잘라 각각 업스케일하고 **겹친 부분을 인페인팅해 잇는다** — 즉 **전체 인페인팅이 한 번 더 도는 셈**이라 인페인팅 강도를 낮게 둔다 |
| 인페인팅 샘플러 | `Original`(= T2I 와 같은 샘플러)을 쓰되 **Compvis 계열(UniPC, DDIM 등)은 동작하지 않아 자동으로 Euler 로 바뀐다** |
| CFG/Steps 에 `0` | **T2I 원본값을 그대로 쓴다** |
| ⚠ 마스크 분리 | 떨어져 있는 마스크마다 따로 인페인팅해서 **횟수가 폭증한다**(얼굴 20개면 20번). **일정 면적 이하 마스크를 버리는 옵션**으로 무의미한 인페인팅을 막는다 |
| ⚠ mediapipe | **confidence 에 너무 민감해 두 명이 있어도 한 명만 마스킹될 때가 잦다** |

설치 오류(`sam`/`dino` 모듈 없음)는 torch 버전 문제이며, 제작자 답변으로는 `torch==1.13.1+cu117`(webui 기본) ·
`torch==2.0.0+cu117`(런포드) · `torch==2.0.0+cu118`(코랩)만 자동 설치를 지원했다.
**`No module named mmdet.core` 의 해법은 → [오류 해결](troubleshooting.md) 의 A1111 계열 표에 있다.**

## 만화 컷라인을 인페인트로 녹이기
<small>⚠️ 2025-05 기준 · 근거 1건</small>

AI 로 뽑은 그림으로 만화를 만들 때 **컷라인이 인위적이고 반복적으로 보이는** 문제의 해법이다 (1건, 2025-05). 도구는 클립스튜디오(또는 무료 메디방).

```text
1. 원하는 구도를 정하고 클립스튜디오에서 칸을 나눈다
   (한 컷으로 한 페이지를 끝내는 장면은 캔버스 크기를 커스텀한다)
2. 각 컷에 넣을 그림을 뽑는다  (글쓴이는 한 컷에 200장까지 뽑은 적도 있다)
3. ★ 페이지 전체를 jpg 로 내보내 그 파일을 WebUI 에 올리고 컷 경계선만 인페인팅한다
4. 다시 클립스튜디오로 가져와 말풍선·효과선·소재를 얹는다   (3·4 는 순서를 바꾸는 편이 나을 때도 있다)
5. 레이어 창에서 채도를 낮춘 레이어를 맨 위에 올리면 전체가 흑백 만화가 된다
```

## 프롬프트로 안 나오면 오려 붙이고 i2i 로 녹인다 (2023, 지금도 유효)
<small>⚠️ 2024-08 기준 · 근거 6건</small>

**프롬프트를 아무리 깎아도 안 나오는 것**이 있다. 그때의 답이 이것이다.

> **이미지를 직접 잘라 붙이고 낮은 디노이즈로 i2i 를 돌려 자연스럽게 만든다.**

2023년의 자캐 대회 출품작에 그 절차가 간결하게 적혀 있다 (84694009, 2023-08).
원하는 앞머리 모양이 프롬프트로 도저히 표현되지 않아서 **첫 번째 그림에서 앞머리 부분을 오려 붙인 뒤 i2i 로 녹여 냈고**, 손도 그림판 노가다로 고쳤다.
**초중딩 미술 시간에 그려 본 게 전부인 사람도 마우스만으로 가능하고**, 필요한 것은 포토샵이나 그림판 같은 아주 기본적인 도구와 i2i 반복뿐이다.

### 결함 하나당 한 번씩 국소 인페인트

한 번에 전체를 다시 뽑지 않는다. **고칠 항목을 먼저 목록으로 정리**하고 하나씩 처리한다 (79179637, 2023-06).

```text
고칠 목록
  1. 아호게와 머리카락      → 그림판으로 형태를 대충 칠해 넣고 그 부분만 인페인트
  2. 오른쪽 목 라인 안 맞음 → 그림판으로 칠한 뒤 인페인트
  3. 입과 윗니              → 입만 따로 인페인트
  4. 눈동자                 → 마지막에 인페인트
```

그 결과물의 구성비를 글쓴이 스스로 **순수 t2i 50% / 인페인트 40% / 그림판 3D 10%** 라고 적었다.
→ 위 '먼저 칠하고 나서 인페인트한다'

### 디노이즈를 점점 낮춰 가며 번갈아 한다

2023년 고퀄 작업의 표준 패턴이다 (72250546).

```text
t2i (denoise 0.55) → 포토샵 1차 수정 → i2i denoise 0.5 → 포토샵 2차 수정
                   → i2i denoise 0.3 → 3D 손 모델링으로 손 수정 → 마지막 i2i → 포토샵 효과
```

**수정 → i2i → 수정 → i2i 를 반복하되 디노이즈를 계속 낮춘다.** 뒤로 갈수록 형태를 지켜야 하기 때문이다.

### 두 캐릭터를 한 장에 넣을 때

> **컨트롤넷과 오픈포즈를 조합하는 것보다 그냥 두 그림을 붙여 놓고 반반씩 인페인트로 프롬을 따로 돌리는 편이 편하다.**
> 확실하게 2인 구도를 잡으려면 **ComfyUI 쪽이 훨씬 낫다** (113562443 댓글, 2024-08).

그 글은 실제로 두 캐릭터를 각각 500장·800장 가까이 뽑아 고른 뒤 그림판에서 합쳤다.
**감정 표현을 강하게 요구할수록 그림체가 흔들리고 얼굴이 무너져 타율이 떨어진다**는 것이 800장을 뽑아야 했던 이유다.
누끼를 따서 붙일 때는 **늘리면 깨지므로 조금씩 오목조목 붙이는 편이 낫다.**

### 모델이 학습하지 않은 물건은 디노이즈에 즉시 뭉개진다 (2023-03)

t2i → i2i → 그림판 → 인페인트를 반복한 수작업 보정 기록에서 나온 교훈이다.

```text
① t2i 랜덤 가챠로 대충 뽑는다
② i2i 업스케일
③ 그림판으로 손을 떼다 붙이고 대충 채색, 가리는 옷 제거 시도
④ 인페인트
⑤ 그림판으로 원하는 형태(여기서는 후크)를 직접 그려 넣는다
⑥ 인페인트
⑦ i2i 마무리
```

> **핵심 교훈 — 모델이 학습하지 않은 물건은 디노이즈를 조금만 올려도 즉시 뭉개진다.**
> 가진 모델을 여럿 바꿔 봐도 소용이 없어 **아주 살짝만 뭉개는 선에서 타협**했다.

- **댓글의 대안** — 그 부분만 인페인트 마스크를 주고 **'마스크 이외 그리기'** 옵션으로 나머지 디노이즈를 올려 본다.
  얼굴은 `ddetailer` 로 다듬는다 → [디테일러](detailer.md).
- **또 하나** — 업스케일 단계에서 관련 태그(밀프 스타일)를 안 넣어 로라 효과가 사라진 것 같다고 스스로 진단했다.
  **i2i·업스케일 단계에도 원하는 특성 태그를 다시 넣어야 한다.**
- **결론은 '이럴 바엔 학습을 하는 게 더 빠르다'** 였다 → [로라 쓰는 법](lora-usage.md).


### 어려운 소재는 프롬프트가 아니라 모델을 갈아 끼운다 (2023-04)

73568623 은 6.25 전쟁 시기 사진 느낌을 내려고 **채널에서 드문 SD2.1 계열**(`V. 2.1_rmadaMergeSD21768_v60`)을 골랐다.
설정은 920x480 · Steps 20 · **Sampler UniPC**(variant `vary_coeff`, skip type `logSNR`, order 1) · **CFG 3** 이다.

## 컨셉 로라가 딸려 그리는 것을 네거티브로 눌러 구도만 남기기 (2023-03)
<small>⚠️ 2023-03 기준 · 근거 2건</small>

인페인트로 고치기 전에, **애초에 원하지 않는 요소가 안 나오게** 하는 방법이 있다.
컨셉 LoRA 를 낮은 가중치로 겹쳐 특수 구도를 만들 때 쓰는 요령이다 (72224411, 2023-03).

'모니터 속에서 걸어 나오는 여자' 구도를 만들기 위해 **'링' 의 사다코 로라(0.6)와 '벽에 갇힌' 로라(0.5)를 낮은 가중치로 겹쳤다.**

```text
긍정   ... (woman on the screen:1.2), my room,
       <lora:yamamuraSadakoTheRing_v3:0.6> <lora:trappedInWall_v2:0.5>,
       trapped in wall, sadako, (through the monitor, big monitor screen:1.15), stuck in wall, wallpaper

부정   ... (gray wall, nsfw, elf ears, wall, big tits, stonewall:1.3), badhandv4
                ↑ wall / gray wall / stonewall 을 강하게 눌러 놓은 것이 핵심
```

**`trapped in wall` 로라가 실제 벽을 그려 버리는 것을 막고 모니터 화면만 남기기 위한 조치다.**

> **일반화하면** — 컨셉 로라는 원하는 구도와 함께 **딸려 오는 요소**가 있다. 그 요소의 이름을 정확히 알아내 **네거티브에 1.3 정도의 가중치로 눌러 놓으면** 구도만 남는다.
> 이것이 안 되면 그때 인페인트로 지운다.

### 덧 — 프롬프트를 길게 쓰는 것만이 답은 아니다

같은 대회의 다른 출품작은 정반대를 보여 준다 (72223830, 2023-03).
**"고봉밥 프롬(수십 줄짜리)을 보고 질려 도망갈 뉴비를 생각해서 최대한 간결한 프롬으로 뽑아 봤다"** 는 것이 컨셉이었다.

```text
긍정   (masterpiece:1.4), (best quality:1.4), (high_resolution:1.4), 8k wallpaper,
       1girl, colorful, Dreamlike, A girl is welcoming the visitor, long messy hair, look at me
부정   easynegative
```

**좋은 병합 모델을 쓰면 이 정도로도 결과가 나온다.**

## 컷 밖으로 캐릭터 내보내기 — 인페인트 스케치 (2025-05)
<small>⚠️ 2025-05 기준 · 근거 1건</small>

AI 만화에서 **캐릭터가 컷(칸) 밖으로 튀어나오게** 만드는 가장 간단한 방법이다 (2025-05, WebUI 기준).

| | |
|---|---|
| 쓸 상황 | **그림 자체가 컷 경계에서 잘려 나온 경우.** 그림이 안 잘리고 온전히 살아 있다면 **클립스튜디오 소재 + 누끼** 쪽이 낫다(댓글도 같은 결론) |

```text
① 1차로 완성된 만화 페이지를 통째로 '인페인트 스케치' 에 넣는다
② 컷 밖으로 튀어나오게 하고 싶은 부분(예: 머리 꼭대기)을 직접 그려 넣는다
③ 인페인트 탭으로 보내 방금 그린 영역을 마스크로 표시한다
④ 디노이즈를 조금씩 조절해 가며 돌려 만족스러운 결과를 고른다
⑤ 작업 툴로 가져가 대사와 효과를 넣어 마무리
```

| 단계 | |
|---|---|


## 포토샵 하모나이즈로 배경 합성하기 — 2D 에서는 소프트라이트 + 낮은 불투명도 (2026-01)
<small>2026-01 기준 · 근거 1건</small>

누끼 딴 인물을 다른 배경에 얹으면 **빛과 색이 안 맞아 붙여 놓은 티가 난다.** 포토샵의 **하모나이즈(Harmonize)** 가 그것을 자동으로 맞춰 주는데,
**2D 애니 그림에 그냥 쓰면 색이 물 빠진 느낌이 되어 애매하다**(158418668).

> **다만 하모나이즈는 빛의 방향과 상호작용은 자연스럽게 받아들인다.**
> 그래서 색은 버리고 빛만 가져오는 식으로 쓴다.

```text
인물 누끼 레이어에 하모나이즈 적용
  → 블렌딩 모드를 소프트라이트
  → 불투명도를 은은하게 낮춘다
```

**기존의 수동 방식**(빛의 방향·블렌딩 종류·색상을 눈으로 보고 맞추기)은 한 장씩은 잘 나오지만
**여러 장을 만들 때 감에 의존해 일관성이 없다.** 그래서 기존 방식 위에 하모나이즈를 더 은은하게 얹는 조합도 유용하다고 한다.

## 합성한 것을 확산으로 녹이는 네 갈래 (2023, 지금도 통한다)
<small>⚠️ 2023-11 기준 · 근거 4건</small>

### ① 합성본을 통째로 인페인트에 태워 경계를 녹인다

```text
  여고생 얼굴만 건드리지 않게 마스크
  1800x1200 / Steps 40 / denoise 0.55 / Mask blur 4
```

거기에 **본체에도 ControlNet `inpaint_global_harmonious`** 전처리기를 `weight 1.0` · `ResizeMode.INNER_FIT` · `pixel perfect True` 로 걸었다.
