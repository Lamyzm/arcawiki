# 디테일러 — 얼굴·손 고치기

> **원문 28건 → 이 문서 하나** · 주장 82개 · 정리 2026-08-14

디테일러는 **얼굴·손처럼 작게 나와서 뭉개진 부분을 자동으로 찾아 확대해 다시 그리는** 도구다. `full body` 한 장을 뽑았는데 얼굴이 죽처럼 나오는 문제의 정답이 이것이다.

**중요 — 채널의 계보가 A1111 을 건너뛴다.** 2023년 `ddetailer`(ADetailer 의 조상) 다음이 바로 2024~2026년 ComfyUI 디테일러이고, **가장 널리 쓰이는 A1111 확장 `ADetailer`(Bing-su)를 다룬 글은 채널에 없다.** 이 문서는 현행 ComfyUI 방식을 앞에, ddetailer 의 개념과 실제 파라미터를 뒤에 두고, 마지막에 **SEGS 대 마스크 병합 · 여러 명일 때 · 배포 워크플로우**를 붙였다.

## 이건 언제 쓰는 것인가
<small>⚠️ 2023-02 기준 · 근거 3건</small>

`full body` 같은 태그를 넣거나 큰 해상도로 한 명을 뽑으면 **얼굴이 뭉개진다.** 얼굴이 차지하는 픽셀 수 자체가 적어서 생기는 문제라 프롬프트로는 못 고친다.

디테일러는 이걸 자동으로 한다.

```
얼굴을 자동 인식 → 크롭 → 확대 → 인페인팅(i2i) → 축소 → 원위치에 합성
```

**왜 중요한가**: 인페인트 탭에 들어가 Only Masked 로 하는 편이 더 정확하지만, **디테일러는 t2i 에서 자동으로 적용된다.** 한 장 뽑고 포토샵 켜서 크롭하고 돌리고 다시 넣는 번거로운 작업이 사라진다(70355715, 2023-02, 추천 100).

이럴 때 쓴다.

- 전신·원경 구도에서 **얼굴이 뭉개질 때** (가장 흔한 용도)
- **손가락**을 다시 그리게 하고 싶을 때
- 눈만 따로 디테일을 올리고 싶을 때
- 옷·소품처럼 **특정 부위만** 다시 그리고 싶을 때 (SAM3 방식)

[인페인팅](inpainting.md)과의 구분: 얼굴·손처럼 **어디를 고칠지 기계가 찾을 수 있는 것**은 디테일러, 사람이 직접 범위를 정해야 하는 것은 인페인팅이다.

## 어떻게 동작하나 — 확대해서 다시 그리는 이유와 배수 규칙
<small>2026-05 기준 · 근거 3건</small>

**왜 확대하나**: 디테일러의 목적은 작은 얼굴의 눈 같은 것을 제대로 다시 그리게 하는 것인데, **확대해서 i2i 한 뒤 다시 축소하는 편이 디테일이 더 살아나기 때문**이다. 축소는 품질이 떨어지므로 하지 않는다(170890690 댓글의 상세 답변).

**배수 규칙(중요)**:

| 항목 | 값 |
|---|---|
| 확대 조건 | 얼굴이 **768px² 이내**일 때만 가져와 **1024px²** 로 업스케일 |
| 리사이즈 배수 — SDXL | **64 배수** |
| 리사이즈 배수 — Anima | **32 배수** (그냥 64 배수로 통일해 돌린다) |

리사이즈는 **모델 latent 크기 배수에 맞춰야 한다.** Impact Pack 의 FaceDetailer 가 `max size` 를 두고 리사이즈하는 것도 같은 이유다.

같은 원리를 노드로 직접 짠 예 — NAI 인페인트 강도 조절 워크플로우는 "마스킹 → 잘라내기 → 업스케일 → i2i → 다운스케일 → 원본에 병합" 순서이고, 작성자 스스로 **"사실상 디테일러와 같다"** 고 적었다(98883845).

Impact Pack 의 Detailer 노드에서 대응하는 파라미터(86146682) —

- **`guide_size`**: 마스크 영역을 이 크기로 업스케일한 뒤 샘플링하고 다시 축소한다. 입력값이 마스크 영역보다 작으면 업스케일 없이 그냥 샘플링한다. **실제 배율은 콘솔에 출력된다.**
- **`Reference range`**: 마스크 주변에서 참조할 영역의 범위. 1, 2, 3 으로 올릴수록 주변을 넓게 참조해 주변과 어우러진다.

## 지금 쓰는 것 — ComfyUI SAM3 디테일러
<small>2026-02 기준 · 근거 1건</small>

2026년 현행 방식이다(161461103, 2026-02). 준비물은 **SAM3 커스텀 노드**와 **WAS Node Suite (Revised)**.

동작 순서:

```
원하는 부분 마스킹 → SEGS 로 변환 → 디테일러로 다시 그림
```

**SAM3 가 뭐가 다른가**: 하나만 감지하는 게 아니라 **자연어로 무엇을 감지할지 지정**하면 그걸 인식한다. `face`, `hand`, `feet`, `person` 뿐 아니라 `clothes`, `skirt` 같은 사물도 잘 잡는다. 대신 워크플로우가 복잡해지고 자원을 더 쓴다.

모델은 최초 실행 시 자동 다운로드되며 **약 3.5GB 이므로 오래 걸린다고 강제 종료하지 말 것.** (예전에는 Meta 허깅페이스 승인 신청이 필요했으나 노드 제작자가 우회 다운로드를 제공한다.)

**SAM3 노드 파라미터**:

| 파라미터 | 의미 |
|---|---|
| `text_prompt` | 감지할 객체. face, hand, tree, house 다 된다 |
| `confidence_threshold` | 감지 민감도. **0 에 가까울수록 아무거나 잡고 1 에 가까울수록 깐깐** |
| `max_detections` | 최대 감지 개수. **-1 이면 제한 없음**, n 이면 초과 시 **점수가 높은 것**을 가져온다 |
| `offload_model` | `false` = VRAM 에 남아 재사용이 빠름 / `true` = RAM 으로 내려 VRAM 절약, 로드는 느림 |

**점수의 의미(실측 예)**: `hair` 로 잡으면 진짜 머리카락이 **0.96**, 빗자루 부분이 **0.65** 로 잡힌다. `max_detections` 를 1 로 하면 0.96 짜리만 남고, `confidence_threshold` 를 0.65 위로 올리면 빗자루가 걸러진다.

모델 파일 경로는 노드마다 다르다 — **ComfyUI 공식 sam3 노드는 `checkpoints` 폴더**, 개인 제작 커스텀 노드는 **`ComfyUI\models\sam3`** 에 넣어야 인식한다(171066955 댓글). 모델은 `https://huggingface.co/Comfy-Org/sam3.1` 에서 받는다.

평가: **"SAM3 가 잘 나와서 yolo 를 대체해도 되겠다"** 는 것이 원문의 총평이다.

## 마스크 병합 — 안 하면 디테일러가 네 번 돈다
<small>2026-02 기준 · 근거 1건</small>

**마스크가 여러 개면 개수만큼 디테일러가 반복해서 다시 그린다.** 시간이 그만큼 배로 든다.

WAS Node Suite 의 **`Masks Combine Batch`** 로 병합한다. house 예시에서 마스크 22개가 하나로 줄었다.

가장 자주 겪는 사례가 **눈**이다.

> `eyes` 로 잡으면 **양쪽눈 / 왼쪽눈 / 오른쪽눈 3개 마스크**가 나오는데, 그대로 SEGS 로 바꾸면 **SEGS 가 4개**가 된다. (마스크가 같은 부분을 따도 입력 마스크가 다르면 다른 영역으로 인식하기 때문이다.) 병합하면 2개로 준다.

단, **마스크를 합쳐도 영역이 서로 고립되어 있으면 SEGS 는 나눠서 처리**한다. 왼쪽 눈과 오른쪽 눈은 떨어져 있으므로 2개로 남는 것이다.

MASK to SEGS 의 나머지 파라미터:

| 파라미터 | 의미 |
|---|---|
| `combined` | 떨어져 있는 SEGS 를 합침 |
| `bbox_fill` | 영역을 박스로 채움 |
| `drop_size` | 일정 크기 이하 영역을 버림 (10 / 20 / 300 비교) |
| `contour_fill` | 도넛 모양이면 안쪽을 채움 |

## crop_factor — 참조 영역의 트레이드오프
<small>2026-02 기준 · 근거 3건</small>

디테일러에서 가장 중요한 한 개의 숫자다.

**`crop_factor` 는 다시 그릴 때 참조할 영역의 크기**다(161461103, 3.0 / 10.0 / 20.0 / 40.0 으로 비교).

SEGS Preview 에서 **밝게 보이는 영역이 실제로 다시 그리는 부분**이고, **어두운 주변 영역은 그릴 때 문맥으로 참고하는 부분**이다. 이 어두운 영역까지 모델이 함께 넣기 때문에 —

| crop_factor | 결과 |
|---|---|
| 크게 | 주변과 잘 어울리는 **일관성 이점**. 대신 **영역이 커질수록 디테일러 성능이 떨어진다** |
| 작게 | 빠르고 디테일이 산다. 대신 **너무 작으면 맥락을 못 읽어 눈동자에 사람을 그려넣기도 한다**(169548769) |

**시간과 성능의 트레이드오프**라는 것이 원문의 표현이다.

실전 조정법: **작은 부위 작업에서 엉뚱한 곳이 그려지면 `crop_factor` 를 5씩 올린다**(168110618).

## 디테일러로 눈 색·표정 바꾸기 — wildcard spec
<small>2026-02 기준 · 근거 1건</small>

디테일러를 인페인트 대용으로 쓰는 방법이다. 잘 안 알려져 있는데 매우 실용적이다.

**디테일러는 KSampler 와 같은 입력을 받으므로 자체 프롬프트를 가질 수 있다.** 일관성 때문에 보통 KSampler 프롬프트를 그대로 가져오지만, **의도적으로 바꾸면 인페인트처럼 쓸 수 있다.**

예를 들어 `face` 를 감지해 디테일러를 돌리면서 프롬프트의 `red eyes` 를 `blue eyes` 로 바꾸면 눈 색이 바뀐다.

**더 간단하게는 디테일러 노드의 `wildcard spec` 텍스트 입력창에 이렇게 쓰면 된다.**

```
green eyes
```

눈 색 변경, 표정 변경 등에 쓸 수 있고, 나중에 리저널 프롬프트를 쓸 때도 도움이 된다.

[인페인팅](inpainting.md)에서 얼굴을 칠하고 표정 태그를 바꾸는 것과 같은 목적을 **노드 하나, 칸 하나로** 처리하는 셈이다.

## 하지 말 것
<small>2026-04 기준 · 근거 3건</small>

**① 감지 대상을 두 개 이상 쓰지 마라.**
SAM3 감지 대상을 두 개 이상 쓰면 **그림에서는 타율이 떨어진다**(실사는 괜찮은데 그림은 하나씩 하는 게 낫다). `face` + `hair` 가 목적이면 **`head` 단일 프롬프트가 낫다**(161461103 댓글).

**② 디테일러를 세 번 연달아 돌리지 마라.**
얼굴 + 눈 + 인페인팅용까지 디테일러가 세 번 돌면 **원본과 딴판이 되거나 오버디테일로 징그러워진다.** 하나만 돌리거나 디노이즈를 낮춰라(168110618).

**③ ANIMA 는 디테일러 궁합이 나쁠 수 있다.**
"ANIMA 는 디테일러와 궁합이 좋지 않은 듯해 **1차 샘플러만으로 뽑는 방식으로 되돌렸다**"는 워크플로우 제작자의 보고가 있다(페이스 디테일러는 남겨 뒀다). 작성자 스스로 ANIMA 본체나 ANIMA 용 컨트롤넷 모두 아직 불안정해 연구가 더 필요하다고 단서를 달았다(171066955, 2026-05). → [ANIMA](anima.md)

**④ 성기 등 일부 대상은 SAM3 가 감지하지 못한다.**
Meta 모델이라 막았거나 학습 데이터셋에 없었을 것으로 추정된다(161461103 댓글).

**⑤ 노드 업데이트로 파라미터 이름이 바뀌었다.**
`comfyui-sam3` 가 업데이트되며 모델 선택이 `sam_model` 이 아니라 **`sam3_model_config`** 로 바뀌었다. 옛 워크플로우를 받았다면 `sam_model` 내용을 그쪽으로 옮겨 붙여야 한다.

## 직접 짜기 싫다면 — 이미 묶여 있는 워크플로우
<small>2026-05 기준 · 근거 2건</small>

디테일러를 노드로 직접 엮지 않아도 된다. **T2i → FaceDetailer → Upscale 이 한 줄로 묶인** 딸깍 워크플로우가 배포돼 있다(110068034, 2024-06, 2024-10 수정). 본문 이미지를 저장해 ComfyUI 창에 드래그&드롭하면 열린다.

- **반드시 새로 설치한 ComfyUI 에서 진행할 것.** 같은 이름의 다른 커스텀 노드 때문에 예상 못 한 오류가 난다.
- 그룹 6번 `Do not Change!` 가 **FaceDetailer 용 bbox 모델과 SAM 모델을 로드하는 자리**다.
- **설치하지 말 것**: `ComfyUI-YOLO`(기능이 겹치는 노드와 충돌 가능), `ComfyUI Universal Styler`, `YCYY-LoraInfo`.

## 2023년 ddetailer — Bitwise 를 집합으로 이해하라
<small>⚠️ 2023-02 기준 · 근거 2건 · **근거 약함** · 자료 엇갈림</small>

ddetailer 는 ADetailer 의 조상이고 ComfyUI 디테일러에도 같은 개념이 그대로 있다. **"얼굴만 고치려는데 배경까지 바뀐다"** 는 문제의 해법이 여기 있다(70372490, 2023-02).

문제: 범위(Dilation factor)를 크게 올리면 표정은 바뀌지만 **머리카락과 뒤 배경까지 싹 바뀐다.** 이때 Secondary detection model 을 쓴다. 추가할 때 **꼭 `person` 으로 설정해서 캐릭터만 인페인팅되도록** 한다(똑같은 모델을 넣으면 의미가 없다).

**Bitwise operation 을 집합으로 기억하라.**

| 설정 | 집합 | 동작 |
|---|---|---|
| 없음 | **합집합** | A, B 순서대로 각각 인페인팅한다 (2번 작업) |
| A&B | **교집합** | A 와 B 가 모두 인페인팅하는 곳만 인페인팅한다 (1번 작업) |
| A-B | **차집합** | A 만 인페인팅하되 A 와 B 가 겹치는 부분은 건드리지 않는다 |

- **`Inpaint model B detections before model A runs` 는 Bitwise 가 '없음'일 때만 켜라.** 안 그러면 이상한 곳에 인페인팅된다.
- **A-B 의 올바른 용법 = 얼굴을 제외한 몸을 수정하는 것.** A 에 `person`, B 에 `face` 를 넣는다. 얼굴 기준으로 빼면 **정수리가 남는데 이때 x offset 은 마이너스, y offset 은 플러스**로 옮기면 몸만 수정된다.
- 감지 모델 경로: bbox 모델(`anime-face_yolov3`)은 `/models/mmdet/bbox`, segmentation 모델(`dd-person_mask2former`)은 `/models/mmdet/segm`. 요즘 ADetailer 의 `face_yolov8n.pt` 같은 이름이 여기서 유래한다(70355715).

**⚠ 충돌 — anime face 단독으로 충분한가?** 같은 글의 댓글에서 상반된 경험이 보고됐다.

| 주장 | 근거 |
|---|---|
| **A&B(anime face + person)를 기본으로 달아라** | anime face 만 쓰면 **사각형으로 크롭하기 때문에 배경도 함께 i2i 가 돌아 위화감이 생긴다.** secondary 로 어느 정도 막을 수 있고, 인페인팅 크기가 줄어 퀄리티도 추가로 오른다 |
| **primary anime face 만 써도 위화감이 전혀 없다** | 다른 사용자의 실사용 반론 |

같은 문제의식이 2026년 ComfyUI 에서는 `crop_factor` 조절로 옮겨 왔다(위 항목 참조).

그 밖에 댓글 지식 — **배경만 바꾸고 싶으면** 인페인트에서 '마스크 이외만 처리'를 선택하고 영역 지정 없이 A 에 `dd-person_mask2former.pth`, B 는 '없음', `Dilation factor (A)` 를 0 으로 하면 더 정확하다. **몸만 수정하는 것은 실용성이 낮다** — 디노이징을 아주 낮추지 않으면 사각형 경계가 눈에 띄고, 낮추면 별로 달라지지 않는다.

설치 시 십중팔구 실패하는 지점: pycocotools 빌드 실패로 `error: Microsoft Visual C++ 14.0 or greater is required` 가 뜬다. **Visual Studio Build Tools 에서 '데스크톱 개발용 C++' 에 체크**해 설치한 뒤 WebUI 를 다시 로드하면 된다(70355715). → [오류 해결](troubleshooting.md)

## 채널에 자료가 없는 부분 — A1111 ADetailer
<small>2026-08 기준 · 근거 11건</small>

**A1111 확장 `ADetailer`(Bing-su) 자체를 다룬 글은 이 채널에 없다.**

`ADetailer` / `애드디테일러` / `After Detailer` / `face_yolo` / `hand_yolo` / `mediapipe_face` / `bbox` 로 검색했으나 **설치법·모델 선택(`face_yolov8n.pt` 등)·권장 디노이즈 값을 다룬 글을 찾지 못했다.**

채널의 계보가 이렇게 건너뛴 것으로 보인다.

```
2023-02  ddetailer (dustysys)         ← 채널이 얼굴 자동 보정을 처음 알린 글
2023-09  Impact Pack Detailer (ComfyUI)
2024-06  ComfyUI FaceDetailer 딸깍 워크플로우
2026-02  ComfyUI SAM3 디테일러
```

그래서 **A1111 에서 ADetailer 를 쓰는 사람에게 이 문서가 직접 줄 수 있는 것은 개념뿐**이다. 다만 개념은 그대로 옮겨 붙는다.

- ddetailer 의 **Bitwise A&B / A-B** → ADetailer 의 감지 모델 조합·마스크 병합 개념
- ddetailer 의 **Dilation factor / offset** → ADetailer 의 mask erosion·dilation, offset
- ComfyUI 의 **`crop_factor`** → ADetailer 의 `Inpaint mask blur` · 참조 영역 개념
- `bbox` = bounding box(대상을 감싸는 사각형), `yolo` = 물체 탐지 모델 계열의 이름. **ADetailer 의 `face_yolov8n.pt` 같은 모델 이름이 여기서 유래한다**(70355715).

ADetailer 관련 언급이 채널에 아예 없는 것은 아니다 — 인페인트 글의 댓글에서 **"얼굴이면 그림판으로 덧칠하고 ADetailer 를 쓰는 편이 낫다"** 는 지적이 나온 정도이며, 그 이상의 설정값 자료는 없다. 필요하면 공식 저장소 문서를 보는 편이 빠르다.


> **보완 (2026-08) — 설명글이 없을 뿐 값이 없는 것은 아니다.**
> 2023년 대회 출품작들이 EXIF 를 통째로 공개하면서 **ADetailer 파라미터가 그대로 남았다.**
> `face_yolov8n.pt` · confidence 0.3 · mask blur 4 · denoise 0.4 · inpaint padding 32 같은 반복값과
> `mask only top k largest` · `use separate steps/CFG` 같은 옵션 사용례는 이 문서의
> **'A1111 ADetailer·DDetailer 의 실제 설정값 — 대회 출품작 EXIF 여섯 벌 (2023)'** 항목에 정리해 두었다.
> 다만 그것은 **출품작 EXIF 이지 사용법을 설명한 글이 아니고, 전부 SD1.5 시절 값**이다.

## 2023년 ddetailer 기본편 — 값은 여기 있다
<small>⚠️ 2023-02 기준 · 근거 1건</small>

앞 항목이 ddetailer 의 **심화편**(Bitwise 집합 연산)이라면 이쪽이 **기본편**이다. 파라미터의 실제 권장값이 여기 있고, 2026년 ComfyUI 디테일러의 값 감각도 여기서 왔다.

**언제 효과가 큰가** — 배경샷·와이드샷·전신샷처럼 **얼굴이 작게 나오는 구도**다. 반대로 와이드샷 학습이 잘 된 모델에서는 차이가 작을 수 있다.

### 절차 (A1111)

1. t2i 에서 뽑은 이미지를 **인페인트로 보낸다**
2. 인페인트 i2i 의 **스크립트 목록**에서 `ddetailer` 를 고른다
3. **주 감지 모델**을 고른다 — 얼굴만 감지하는 모델과 몸 전체를 감지하는 모델이 있고, **얼굴 모델은 얼굴 포함 주위를 사각형 모양으로** 인페인트한다
4. 값을 맞춘다 (아래 표)
5. 프롬프트·샘플링 방법·스텝·CFG 는 **t2i 에서 쓴 것과 동일**하게 두고 디노이즈만 낮춘다

### 값

| 항목 | 권장값 | 뜻 |
|---|---|---|
| `Detection confidence threshold %` | **30** | 마스크가 자동으로 안 씌워질 때 낮추는 값. 이상 없으면 30 |
| `Dilation factor` | **20~30** | 마스크 크기 확대. 얼굴은 사각형으로 잡히므로 얼굴 전체를 덮으려면 넉넉히 |
| `X / Y offset` | 0 | 마스크를 축 방향으로 옮긴다. 거의 쓸 일이 없다 |
| 디노이즈 강도 | **0.5 미만** (제작자 권장) | 너무 높으면 원본과 **다른 얼굴**이 된다 |
| 전체 해상도로 인페인트하기 | **체크** | t2i 에서 바로 쓸 때 제작자가 권장 |

### 사각형 마스크가 싫을 때 — 두 모델의 교집합

얼굴 모델이 얼굴 주위를 사각형으로 뭉텅 잡는 것이 이 도구의 약점이다. `Secondary detection model` 에 몸 감지 모델을 넣고 **`A & B`(교집합)** 연산을 쓰면 얼굴 윤곽만 정확히 마스킹된다.

**단, 몸 감지 모델은 머리카락까지 강하게 인식한다** — 단발이면 쓸 만하지만 **장발은 통으로 잡힌다.**

마스크 미리보기(얼굴 초록 사각형, 몸 파란 영역)는 생성 미리보기 첫 단계에 잠깐 뜨는 것이며, **ControlNet 을 켜면 안 뜬다.** → [컨트롤넷](controlnet.md)

> **2026년 대응** — 같은 일을 ComfyUI 의 Impact Pack `FaceDetailer` 가 한다. 값의 성격(감지 신뢰도 / 마스크 확장 / 낮은 디노이즈)은 그대로 옮겨 온다.

## SEGS 로 따로 돌릴까, 마스크를 병합할까
<small>2026-06 기준 · 근거 2건</small>

디테일러에 마스크가 여러 개 들어왔을 때 처리 방식은 둘 중 하나다. **이것이 시간과 결과를 가른다.**

| 방식 | 동작 | 대가 |
|---|---|---|
| **SEGS** | 떨어져 있는 마스크를 **전부 따로** 샘플링 | 마스크 개수만큼 시간이 걸린다 |
| **마스크 병합** | 하나로 합쳐 **한 번만** 샘플링 | 빠르지만 각 부분을 확대해 다시 그리는 이득이 준다 |

앞 항목(마스크 병합)에서 본 '안 하면 디테일러가 네 번 돈다' 는 문제의 뒷면이 이것이다 — **네 번 도는 것이 항상 낭비는 아니다.** 얼굴 넷이 화면 곳곳에 흩어져 있으면 SEGS 가 맞고, 눈·입처럼 한 얼굴 안에 몰려 있으면 병합이 맞다.

### 프롬프트는 어디서 오나 — 세 가지 모드

| 모드 | 무엇을 쓰나 |
|---|---|
| 그대로 사용 | 본 생성에 쓴 프롬프트를 그대로 |
| 지정 마스크별 프롬프트 | 마스크 번호(1~6)마다 다른 프롬프트 |
| **태거 사용** | crop 한 이미지에서 **마스크 부분만 남기고 나머지를 단색으로 칠한 뒤** 태거 모델이 뽑은 태그를 프롬프트로 쓴다 |

세 번째가 재미있다 — 무엇을 고쳐 그릴지 사람이 안 적어도 되게 만든 것이다. 태거가 무엇인지는 [용어집](glossary.md).

캔버스형 도구에서는 마스크를 클릭해 **1~6번 번호**를 붙이고, 그 번호가 프롬프트 노드의 같은 번호 칸과 연결된다. 마스크 레이어를 겹쳐 만들 수 있고 두 레이어를 모두 선택하면 상단 레이어 기준으로 중복 부분을 제거할 수 있다.

## 여러 명일 때 — 리저널 호환 디테일러
<small>2026-05 기준 · 근거 1건 · **근거 약함**</small>

두 캐릭터를 리저널 프롬프트로 뽑아 놓고 디테일러를 돌리면 **얼굴과 눈 색이 뒤바뀐다.** 디테일러는 어느 얼굴이 누구인지 모른 채 '본 생성 프롬프트' 를 그대로 다시 먹이기 때문이다.

채널 이용자가 임팩트 디테일러를 **리저널 호환으로 개조**해 이 문제를 없앴다 — 영역별 프롬프트를 그대로 적용해 **얼굴·눈색이 바뀌지 않는다.**

디테일러에만 다른 프롬프트를 주고 싶으면 리저널과 같은 문법을 쓰고 `area_layout` 을 연결해야 한다.

```
<base>       공용 로라 · 공통 배경 · 스타일 · 둘의 행동과 구도
<area1>      1번 영역 캐릭터
<area2>      2번 영역 캐릭터
```

## ⚠ 디테일러가 마스크 밖 엉뚱한 데를 그린다 — 범인은 컨트롤넷이다 (2026-04)
<small>2026-04 기준 · 근거 1건</small>

**"마스킹은 멀쩡한데 디테일러가 크롭한 자리에 엉뚱한 영역이 그려져 들어간다"** —
크롭 팩터를 올려 가며 덮어 온 이 고질병의 원인이 2026-04 에 규명됐다. **범인은 컨트롤넷이다.**

### 증상

| | |
|---|---|
| 언제 | **마스킹 영역이 작으면서 `crop_factor` 수치도 낮을 때** |
| 어디서 | **디테일러**, 그리고 **크롭&스티치처럼 내부 로직이 비슷한 노드**에서만. **일반 KSampler 에서는 나타나지 않는다** |
| 착각하기 쉬운 것 | 인페인팅뿐 아니라 **일반 t2i 용 디테일러에서도 같은 조건이면 똑같이 일어난다.** 보통 디테일러는 낮은 디노이즈로 돌리니 티가 잘 안 날 뿐이라, **"프롬프트를 못 알아들어 찐빠가 났다" 고 오해하기 쉽다** |

### 원인 — 크롭된 이미지에 크롭 전 좌표가 들어간다

디테일러는 **대상 영역을 크롭해 새로 그린 뒤 원본에 다시 붙이는** 방식이다.
그런데 **크롭되어 작아진 이미지에 컨트롤넷이 크롭 전 좌표 기준의 데이터를 그대로 밀어 넣어서** 위치가 어긋난다.

### 해결 — 컨트롤넷과 디테일러의 연결을 끊는다

```text
컨트롤넷  →  일반 KSampler (한 번 생성)          ← 여기까지만
프롬프트  →  디테일러                            ← 컨트롤넷 없이 직결
```

컨트롤넷 때문에 망가지는 경계선과 디테일은 **컨트롤넷 없이 프롬프트에 직결한 디테일러로 잡는다.**
**`crop_factor` 를 10씩 크게 잡아 어거지로 덮는 것보다 훨씬 원활하다**(대신 노드 구성은 더 난잡해진다).

> **부수 문제 하나** — 인페인팅 컨트롤넷을 KSampler 만으로 뽑으면 간간이 **마스킹 바깥 영역까지 전체적으로 살짝 뭉개진다**(정확한 조건은 미상).
> **마스킹 이외 영역에 원본 그림을 다시 붙여 넣는 노드를 추가해** 해결했다.

*(한 글에서 규명됐지만 증상 조건·재현 범위·해결이 모두 구체적이고, 같은 증상 보고가 채널에 반복돼 왔다.)*

## SAM3 디테일러 실전 — `face and neck`, 그리고 소개자가 되돌아간 곳
<small>2025-12 기준 · 근거 1건</small>

SAM3 디테일러를 실제로 돌리면서 나온 것들이다 (2025-12).

### 감지 프롬프트 — `face` 보다 `face and neck`

`face` 로만 잡으면 찐빠가 날 때가 있어 **`face and neck` 으로 하면 목까지 범위가 넓어져 덜 난다.**
다만 **머리카락 경계가 어색해지는 문제는 남는다** — 머리까지 디테일러를 돌리면 머리 스타일이 바뀌고, 머리를 빼면 눈썹 같은 것이 어색해진다.
디테일러는 누끼처럼 딱 잘라 처리하는 것이 아니라 **조금 넓게 잡아 맥락을 보고** 처리하므로,
사이즈를 늘리거나 블러를 주거나 `crop factor` 를 늘리는 등 **각자 노하우가 갈리는 영역**이다.

### 설치·미싱에서 막힐 때

| | |
|---|---|
| SAM3 세그멘테이션 노드가 미싱 | 노드 검색에서 **`sam3` 를 직접 찾아 설치**한다 |
| 모델 위치 | `(ComfyUI 설치 경로)\ComfyUI\models\sam3\sam3.pt` |
| `set basic` · `get basic` 이 미싱으로 남는다 | **보기 편하게 하는 UI 노드일 뿐이라 직접 직결해서 써도 된다** |
| 그래도 꼬였으면 | **sam3 관련 노드를 전부 지우고 `ComfyUI-RMBG` 만 다시 깐 뒤** `models/sam3` 에 `sam3.pt` 를 넣어 **RMBG 만 그 모델을 쓰게** 하면 해결된다 |
| `MaskDetailerPipe` 에서 `'Tensor' object has no attribute 'copy'` | **SAM3 노드 연결 실수**였다 |

노드 자체가 깨져 로드되지 않는 경우는 [오류 해결](troubleshooting.md) 의 'SAM3 커스텀 노드 되살리기' 항목이다.

### ⚠ 소개한 사람이 결국 되돌아간 곳

> **글쓴이는 요즘 이 SAM3 디테일러를 안 쓰고 `https://huggingface.co/Bingsu/adetailer` 를 페이스 디테일러에 쓴다.**
> **무겁고, 기존 디테일러가 손대지 않던 곳은 오히려 건드리면 이상해지는 경우가 많아서**다.

SAM3 디테일러가 값어치를 하는 곳은 **희귀한 부위·작은 부위·기존 디텍션 모델이 잘 못 잡는 대상**이다.
평범한 얼굴 보정이라면 기존 face 디텍터 쪽이 가볍고 안전하다는 것이 원 소개자의 결론이다.

*(리저널로 두 캐릭터를 넣는 것은 프롬프트만으로도 되지만 **로라까지 영역별로 분리하는 것은 아직 실험적이라 영역이 겹치면 섞인다.**
얼굴이 겹치면 대참사가 나므로 POV 로 구도를 잡거나 얼굴 영역을 떨어뜨린다.)*

## 수동 마스크 디테일러 — ComfyUI 안에서 얼굴을 지우고 다시 그리기 (2026-08)
<small>2026-08 기준 · 근거 1건</small>

```text
③ I2I 로 얼굴만 새로 그린다
```

### ② 마스크 편집기 여는 법과 도구

**이미지 로드 노드를 우클릭 → `Open in MaskEditor | Image Canvas`.**

왼쪽 툴은 위에서부터 **마스크 영역 그리기 / 선 그리기 / 지우개 / 전체 마스크 채우기 / 부분 마스크 채우기** 인데
**여기서는 '마스크 영역 그리기' 와 '선 그리기' 둘만 쓴다**(지우개는 선 그리기에서 우클릭으로도 지워져 굳이 필요 없다).
오른쪽 탭에서는 **색상 선택기(스포이드) · 두께 · 레이어 표시 토글**만 쓴다.

| 순서 | |
|---|---|
| 1 | **스포이드로 주변 색을 찍고 '선 그리기' 로 얼굴을 덮어 지운다.** 디테일러를 돌릴 것이므로 완벽하게 지울 필요는 없지만 **머리카락과 겹친 부분까지 지우는 편이 좋다** |
| 2 | **'마스크 영역 그리기' 로 얼굴을 마스크로 지정**한다 |
| 3 | ⚠ **위쪽 하늘색 저장 버튼을 반드시 누른다** |

### ③ 얼굴만 바꾸기 — 그림체를 T2I 와 똑같이 맞춘다
